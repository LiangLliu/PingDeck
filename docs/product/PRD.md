# 产品需求基线

这份需求基线用于判断 SpanBay 应解决哪些工作问题、一次操作怎样才算完成，以及哪些边界必须向用户说明。它不规定按钮位置、数据库字段或交付批次。

- [产品手册](../product.md)解释对象、作用域和操作语义。
- [系统架构](../architecture.md)解释执行、数据与信任边界。
- [决策记录](../decisions.md)解释仍需维护的取舍；[设计规范](../design.md)负责交互和视觉。

## 1. 用户、问题与产品目标

### 用户在什么场景使用

| 用户与场景 | 当前工作的困难 | SpanBay 应交付的结果 |
| --- | --- | --- |
| 后端或测试工程师接入、联调、排查 HTTP 接口 | 请求配置、环境、脚本、响应和失败证据分散，修改后难以复现 | 从草稿发出真实请求，定位变量、认证、传输或断言问题，再保存成可重复使用的请求、Mock 或 Flow |
| AI 工程师接入多个服务商，并供编码客户端使用 | 兼容协议不等于模型可用；密钥、模型名与故障转移散落在客户端配置中 | 验证服务商与模型，按“服务商/模型”名字与备用规则建立可解释的路由，通过本地网关连接客户端并核实真实请求 |
| 需要智能体协助排错或改代码的工程师 | 粘贴上下文容易泄露凭据；自动执行的权限和副作用不清楚 | 从工作台带入有限上下文，审阅工具动作、批准或拒绝，最后复核回答、调用证据和文件变更 |

这三类工作会交接。例如，网关失败日志可以交给 Chat 分析，但打开对话本身不应发送日志、调用模型或修改配置。

### 目标

1. 缩短“构建调用 → 得到证据 → 修正 → 固化”的路径，保留失败与取消的区别。
2. 让 AI 服务的实际目标、协议转换、用量与费用可以追查，不以一个成功状态掩盖路由变化。
3. 让本机数据和执行权限由用户控制；在不可逆、越界或扩大网络暴露面之前给出足够信息。
4. 在较大的请求集合、响应和流式对话下保持编辑可用，避免后台任务拖动整个界面。

目标不以模块数、命令数或源码行数衡量。一次端到端任务能否复现、解释和停止，比覆盖更多菜单项重要。

## 2. 范围与承诺等级

这里的“应”是验收要求，不把已有代码直接当作合理依据。各节同时标明当前实现边界；已知差距不能靠删除要求结案。

| 类别 | 范围基线 |
| --- | --- |
| 当前范围 | 桌面 HTTP/GraphQL 与 AI 调试、本地 Mock、顺序 Flow、历史与环境、服务商与本地网关、智能体对话、文件夹同步 |
| 设计目标 | 可解释的失败、有限权限、可复核的副作用、流重连恢复、数据不因切换模块而误归属；性能目标见第 8 节 |
| 当前不提供 | WebSocket/gRPC 执行、云端托管 Mock、账号与团队协作服务、监控平台、应用 CLI、任意协议的无损转换 |
| 不构成发布承诺 | OS Keychain/库加密、Windows shell 沙箱、MCP OAuth、自动更新、整轮文件回滚、音视频执行（无排期） |
| 评估后暂缓 | 评估过、有意推后的五组能力，列在表后；重新排期前先在 `docs/decisions.md` 写决策 |

评估后暂缓的能力：

- 用量：延迟分位数（要加直方图列）。“今天”“本月”“上月”按本地自然日起算，其余范围是截至此刻的滚动窗口；首 token 时间的平均值来自调用日志，只覆盖日志还保留的调用。
- 智能体能力：自动记忆、自定义子智能体、自定义命令、钩子、插件。
- 模型角色：用户自定义角色、按对话覆盖角色、压缩与自动标题用快速角色、用量按角色分组、按角色的并发上限、自动级联、子智能体嵌套到第 2 层。
- 备用模型：请求体里的 `models` 数组、会话级备用链、按客户端区分的网关规则。
- 密钥分组：自动读取 new-api 的分组名、分组单独的轮换方式、按分组排价格优先级。「重试与故障转移」页要说明“换密钥也占重试次数”。

明确不做的能力（D-278 与对应的范围裁剪），界面上不留入口：

- 声明式 AI 断言。代价：AI 步骤只能用 HTTP 断言和脚本判定。有稳定的评测需求和样本时重议。
- Flow 步骤停用、总会执行与分组，按数据行循环与多次试跑汇总。代价：长流程不能临时跳过某一步。流程长到需要分组或数据驱动时重议。
- 智能体运行详情抽屉与发送测试通知的入口。代价：诊断看右栏与历史，排查通知要真触发一次审批。右栏装不下诊断信息、或通知权限成为常见问题时重议。
- 环境机密值的限时查看。代价：已存机密只显示尾号，只能复制。用户常需核对原文时重议。

“本地优先”指应用在本机保存主要工作数据，普通数据管理无需登录服务。它不等于离线 AI、零网络、端到端加密或同机恶意程序无法读取数据。请求、模型调用、探测、搜索、MCP 和代理/回调可能访问网络；启用的定时余额或目录刷新也会发请求。

## 3. 闭环一：构建、发送、排错、固化

### 主路径

用户选择工作区与环境，创建或导入请求，检查变量、认证、脚本与网络选项，发送并检查响应。确认行为后，把请求保存进集合；需要稳定替身时建立 Mock，需要多步验证时建立 Flow。

保存请求描述“以后怎样调用”；发送记录描述“这一次发生了什么”。两者不能互相替代。重新发送历史条目也不是时间旅行：服务端状态、密钥、文件与路由可能已经变化。

### 关键验收

| 场景 | 用户应能观察到的结果 |
| --- | --- |
| 正常发送 | 响应回到实际发送的标签，显示状态、耗时、大小和可用的调用链；切换标签不能把结果写给另一份草稿 |
| 变量未解析、文件不可用或认证未补齐 | 在主请求发送前指出具体问题；不把校验失败显示为 HTTP 响应。前置脚本可独立联网，见下方边界 |
| 受保护环境 | 按本次调用实际使用的环境和方法确认；集合/Flow 在开始前确认一次。拒绝后主请求不发送，前置脚本扩大方法时重新检查 |
| 网络失败 | 区分连接、超时、TLS 等可识别原因与服务端 HTTP 错误；列出已发出的尝试信息，不用重复重试掩盖最终失败 |
| HTTP 成功但断言或后置脚本失败 | 保留响应，同时标明检查失败；不能只用绿色状态码宣称任务通过 |
| 用户停止 | 尚未派发的主请求不发送；在途操作尽力中止，显示取消或部分结果，不宣称服务端已回滚 |
| 编辑与保存 | 未保存草稿不改变已保存请求；保存失败保留可修正的编辑内容。关闭脏草稿应有保存、丢弃、取消分支 |
| 环境草稿 | 未保存变量不参与执行；用户能分辨生效环境与正在编辑的环境 |
| 固化为 Flow | 顺序执行、“仅当…时运行”的条件、抽取、断言、重试和遇错停止可解释；步骤判定计入请求自带断言；抽取与局部变量只在本次运行内传递，机密提取值打码 |
| Flow 失败或取消 | 显示已经完成、失败、跳过的步骤与尝试次数；不继续执行本应停止的后续步骤；已完成步骤不回滚 |
| 固化为 Mock | 配置保存与监听启动分开；端口冲突可见。命中日志能用于复核路由，或转成请求草稿/新路由，转换不自动发送 |
| Mock 选响应 | 与 Mockoon 一致：无规则的响应不算命中，规则都不中时返回默认响应；Demo 与桌面结果相同 |
| 重新导入集合 | 同名集合可选“更新”或“替换”：配对上的请求保留 ID，Flow 步骤与历史不断；“更新”保留用户补的断言与脚本；都能撤销 |
| 超大或不完整响应 | 明确截断、缓存失效或格式化失败；预览和已捕获大小不冒充原文和真实大小。超上限可把完整正文存到文件；响应头后超时或停止保留已收部分。句柄失效时可重发 |

### 当前行为与不能承诺的部分

- Flow 的每次已发送步骤尝试写入 `source = flow` 的历史，运行摘要保留最近 20 次；不把响应 Cookie 写回 Cookie Jar。
- Flow 抽取值是临时值，但脚本对环境、集合或全局变量的写入会持久化；凭据名或令牌形状的新变量存为机密，不随导出与同步带出明文。前置脚本提交的修改可能在主请求失败或取消后仍存在；它不是一个原子工作流。
- 请求结果、历史和 Cookie 不组成一次覆盖全链路的事务。历史没写成时响应旁标明“未保存到历史”，失败的发送没写成历史时失败卡同样标明。Cookie 写入失败与没保留的 Set-Cookie 在响应的 Cookie 标签里标明。其余持久化错误记到诊断日志（`logs/spanbay.log`），“复制诊断”附上最近的错误摘要。用户不能把“已收到响应”等同于“证据已可靠保存”。后者是可见保存失败要求的现有差距。
- “Production”只是用户配置的保护标签。普通执行默认只保护非安全方法，可另选保护 GET/HEAD/OPTIONS；脚本 `pm.sendRequest` 受同一个生产确认守卫，没有确认时受保护的方法被拒。不得称为生产环境的完整访问控制。
- Postman 导出是有损的：单请求超时、重试和代理没有对应字段，导出时列为警告；复杂 JSONPath 断言与 AI 断言在 Postman 里写成跳过的测试，只在重新导入 SpanBay 时还原。重新导入按方法加 URL 路径和目录内名称配对，不记录上次导入的基线，所以“更新”是两方合并，不是三方合并：文件删掉的参数或请求头不会从已存请求里移除。
- 当前取消不会为被中止的那次请求新增普通历史行；前面已完成的步骤、变量修改及远端副作用保留。HTTP 重试与 Flow 步骤重试是两层机制，Flow 的一条历史可能包含执行器内部的多次传输尝试。

对应实现见 `crates/spanbay-app/src/app/flow_service.rs::flow_run_impl`、`execution_service.rs::Persistence`、`prod_guard.rs`，以及 `app/tests/items.rs` 的 Flow 重试历史和运行前确认测试。

## 4. 闭环二：接入服务商、验证、路由、连接客户端

### 主路径

用户提供 base URL 和可选密钥，查看发现证据后决定是否保存。再对所需模型做真实能力测试，复核结果后应用；配置备用规则与客户端允许范围，启动网关，预览并写入客户端配置，最后验证实际客户端流量。

“地址被识别”“密钥被接受”“模型回答成功”“某能力被观察到”是不同结论。用户必须能看出哪些有实测依据、哪些只是预设或目录信息。

### 关键验收

| 场景 | 用户应能观察到的结果 |
| --- | --- |
| 发现服务商 | 扫描展示端点、错误与证据，部分结果可以保留；保存必须由用户发起，取消扫描不等于添加服务商 |
| 真实探测 | 执行前说明可能产生费用；停止保留已完成单元格，未运行、超时、限流与不支持不得混为一类 |
| 能力判断 | 未观察到 Tools/Reasoning/Cache 等内容不直接等同“不支持”；目录声明不覆盖更新的实测证据 |
| 应用测试结果 | 用户先复核影响，再显式应用模型启用与能力变化；可撤销应用，不静默改路由 |
| 按模型名调用 | 模型名就是“服务商/模型”，没有别名；展示请求名与实际目标，备用切换、密钥轮换和最终失败可追查；未知裸名只在客户端显式开启映射时交给默认模型，并记原请求名 |
| 协议转换 | 无法承载的特性要拒绝，字段表未登记的字段跨协议一律拒绝，允许丢弃的字段要有转换说明；请求的输出上限高于目标上限时收紧并记转换说明；不得宣称所有客户端功能无损 |
| 流式中断 | 首个内容前允许受控故障转移；首个内容后出错明确结束该流，不拼接另一模型的回答冒充一次完成 |
| 网关访问被拒 | Host/Origin、无效令牌或模型范围失败应阻止上游调用；开启 LAN 或额外允许 Host 时必须开令牌；模型范围也约束备用目标 |
| 连接客户端 | 写入前展示脱敏差异与目标路径（经符号链接时展示真实落点）；预览后文件变化则拒绝覆盖并要求重审；失败要说明是否恢复了已改文件 |
| 写入后的验证 | 区分 loopback 探针成功与真实客户端首请求已到达；不能凭“配置文件写入成功”宣称客户端已连通 |
| 轮换、撤销与恢复 | 旧令牌立即失效；恢复旧配置若包含已撤销令牌，须说明恢复文件不恢复令牌有效性 |

### 现有边界

扫描主要发送不带模型内容的发现/空体请求，但宽松服务端可能对空请求执行短补全；可选的真实验证会计费。因此“零 token、绝不计费”不是承诺。探测结论也只证明所测时刻、模型和样本。

网关日志和捕获有保留及队列上限，拥塞时可丢捕获或日志，不是财务账本。成本可能来自估价，未知价格不应显示为已知免费；USD 与 CNY 分开呈现，不自动换算。逐客户端可设每分钟请求数、同时请求数、每日与每月预算（按一种币种计）、每日与每月 token 数和令牌到期日；预算读用量汇总，有约 10 秒的滞后，价格未知或币种不同的调用只计入 token 限额。

网关、扫描与配置写入的实现分别在 `crates/spanbay-llm/src/llm/gateway/{chat.rs,fields.rs}`、`crates/spanbay-llm-ops/src/llm/sniff/route_probe.rs`、`crates/spanbay-client-config/src/write.rs`；对应网关跨协议/中途断流测试与配置写入冲突测试。

## 5. 闭环三：带上下文的智能体执行与复核

### 主路径

用户从失败响应、历史、网关日志或探测结果打开 Chat，复核有限的上下文与输入草稿，选择模型、文件夹和权限，再发送。模型提出工具动作时，核心作权限判定；需要审批则展示实际动作。用户批准或拒绝，最后检查回答、工具结果、文件差异与实际服务目标。

用户不必给文件夹才能讨论接口或读取已附加文本。选择文件夹也不等于信任其指令；信任、执行模式和单次授权分别表达不同意图。

### 关键验收

| 场景 | 用户应能观察到的结果 |
| --- | --- |
| 从工作台交接 | 只创建带上下文的草稿，用户发送前不调用模型；不存在的对象可说明缺失，不转而读取其他对象 |
| 上下文外发 | 发送前可查看目标与携带内容；秘密字段尽力脱敏。用户主动粘贴的正文、附件和项目文件仍可能包含敏感信息 |
| 只读或计划模式 | 不提供写工具；即使模型伪造调用也由核心拒绝，不能只靠系统提示词约束 |
| 等待批准 | 展示完整命令/路径/目标与原因，拒绝前不执行该动作；默认授权范围有限，不能把一次批准升级为全局授权 |
| 拒绝或超时 | 工具得到“未执行”的结果，保留拒绝原因；过期卡片不能再次触发动作 |
| 窗口不在前台 | 等待批准、提问、计划批准或费用暂停时默认发系统通知；运行结束通知在设置里开，只报 30 秒以上的运行；通知只写对话名、工具类别与风险或结果，不写命令、路径和参数 |
| Full access | 用户显式选择，持续到应用重启；保留硬阻止、Block、强制询问与沙箱；未受信任 MCP、出处不明的抓取主机与 shell 远端命令仍询问；没有沙箱时另行确认 |
| 未绑定对话 | 可以发送；不提供依赖绑定的工具，模型被告知没有工作区；头部给出绑定入口（没有工作区时给创建入口），绑定后下一条消息起生效 |
| 工作区切换 | 运行沿用对话首次发送时绑定的 SpanBay 工作区与环境，不随壳层切换；空闲时可在对话头部改绑或补绑；工作区被删后对话保留，改绑前不能发送 |
| 停止与排队 | 停止当前工作，不自动执行尚未开始的后续指令；失败、步数上限等结束时队列暂停供用户处理 |
| 页面重载 | 同一应用进程内的运行继续，界面重新订阅并补齐；旧审批观察者失效，不能让无人查看的审批无限等待 |
| 应用进程退出或崩溃 | 重启后显示中断，不声称恢复原进程的执行；旧进程与文件日志按可证明的信息修复，不盲杀复用的 PID |
| 文件修改 | 能查看差异与逐文件撤销；读后文件发生变化时拒绝覆盖，撤销遇到外部改动也要求复核 |
| 结果复核 | 工具失败与整个运行失败分开呈现；已完成回答不自动证明修改正确，删除对话/分支不删除或回滚磁盘文件 |

MCP stdio 服务器是本机外部进程，不受 Chat shell 沙箱保护。安装或启用 MCP 等于选择运行该程序；工具审批不能约束服务器启动时自行做的事。导入的新配置或变化配置必须先复核。

## 6. 智能体运行资源规范

限制防止无人响应的审批、队列和进程无限占用资源；它们不构成供应商费用的硬上限。未知价格、已发出的请求和外部工具费用不在本机估算的保证范围内。

#### Run limits (normative)

| Limit | Value | Range or owner |

| Concurrent top-level runs | 3 | Settings › AI › Agent › Limits, 1 to 8 (`MAX_CONCURRENT_RUNS`) |

| Steps per run (each sub-agent has its own) | 20 | Settings › AI › Agent › Limits, 1 to 100 (`MAX_STEPS`) |
| Approval wait, foreground chat | none | 前台已打开的对话不超时 |

| Replay buffer per run | 4,096 events or 1 MiB, whichever is smaller | 常量（运行结束后保留 10 分钟，`REPLAY_EVENTS` / `REPLAY_BYTES`） |

此表固定在本路径。`cargo xtask check-docs`（`npm run check:docs`）解析英文行键，比对值单元格与 `crates/spanbay-agent/src/agent/limits.rs` 的常量；`limits.rs` 的测试比对常量与设置默认值。修改值须同时改 `limits.rs`、`AiAgentSettings::default()`，并审阅资源行为。

“前台”指对话有附着视图且主窗口有焦点：窗口失焦期间按无人值守计时，回到焦点即清零。审批、计划批准与费用暂停共用这条规则；审批超时回“未执行”，计划超时停在计划，费用暂停超时以费用上限结束运行并暂停队列。

## 7. 数据、同步与安全需求

### 数据归属和丢失风险

- 工作区数据操作必须按工作区验证归属；伪造其他工作区的对象 ID 应得到未找到，不得读写对方记录。工作区不是抵御同一用户进程的安全容器。
- 配置、请求草稿、执行证据和运行中的任务应分别说明保存位置与恢复能力。只复制主数据库不是完整备份；配置同步也不包含全部历史、对话、附件或运行状态。
- 数据库只认当前 schema 版本，应用不自动迁移（D-262）。版本更低或更高的库不打开：启动时把它连同同名 `.secrets` 秘密库、日志文件与附件目录改名为带 UTC 时间的 `.bak` 文件留在原目录，新建空库，并弹窗写出每个备份文件的位置。「设置 › 数据与同步」可以在运行中写出数据库与秘密库的一致副本（秘密库副本仍是明文，权限 0600）。首次对外发布前要补上前向迁移。
- 凭据写入后，常规列表与编辑 DTO 只返回提示和是否存在；“未修改”保留秘密，“清除”删除秘密。明文凭据直接写进普通请求、正文或文件时，不会自动得到同等存储保护。复制为代码、集合导出与文件夹同步共用同一套凭据位置：认证字段、凭据名请求头、凭据名查询参数与表单字段、URL 用户信息，以及 Flow 内联步骤的同类位置。集合导出默认把这些位置的字面量留空，用户勾选后才写出原值（D-272）；同步默认写成占位符。
- 本地保险库未加密，文件权限只能限制通常的跨用户读取；有当前用户权限的软件、备份及用户主动导出的秘密仍可能读取值。界面不得声称 Keychain 或已加密。

### 配置同步验收

1. 导入前能预览增加、变更、移除、冲突和危险配置，预览不改变本地数据。
2. 坏文件、非法 manifest、超大文件、冲突标记、读不了的子目录、符号链接目录或云盘未下载的占位文件阻止读取，不能跳过后把其对象当作删除。
3. 删除须显式选择；时间较新的本地版本默认保留，用户可选择传入版本。相同时间由传入副本胜出，不自动合并字段。
4. 导入结果逐项报告已应用、保留和失败；当前按实体应用，可能部分成功。中断后应重新预览，不能假定全量回滚。
5. 秘密默认导出占位符；客户端令牌与 TLS 口令不导出。服务商 host 变化时默认解除本地密钥，不把密钥交给新主机。
6. 自动导出遇到未导入的外部变化（含其他机器的删除，以及本机较新但未看过对方改动的交叉编辑）或读取错误应停止并说明，停止原因在重启后仍可见；不能覆盖其他机器改动或写回其删除来“修复同步”。

文件夹可由 Git 或云盘搬运，SpanBay 不提供云端协调。时间戳、机器时钟与文件系统竞争仍可能影响胜负；它不是多用户协作合并协议。

### 网络与工具边界

普通 HTTP 调试允许用户访问本机/内网，智能体派生请求、网页抓取、扫描和 AI 自定义目标采用更严格且不同的网络策略。不能用一个“已防 SSRF”标签覆盖这些入口。

出站代理按一条规则选择：请求或服务商自己的代理、本地地址与 `no_proxy` 直连、全局代理，全局也留空时走系统代理（D-268）。直接受控连接会校验并钉扎地址；经显式代理或系统代理时由代理解析域名，SpanBay 只按字面量判定，无法保证代理端 DNS 钉扎。LAN 网关与额外允许 Host 会扩大暴露面，令牌不提供 TLS 加密，隧道风险由用户承担。

日志脱敏覆盖已知键名与足够长的已存秘密，不是通用敏感信息识别。实时响应、普通正文、附件、工具输出、短秘密和未知编码仍需用户审阅；脱敏后的捕获也不应默认视为可公开材料。

## 8. 性能、平台与可操作性

下表记录 D-61、D-73、D-130、D-214 的设计目标，来源语义见[决策索引](../decisions.md#12-源码仍引用的旧编号索引)。这些目标不是实测结果；性能报告须注明构建、平台、数据量与测量方式。

| 场景 | 设计目标 | 验证条件 |
| --- | --- | --- |
| 暖启动外壳首绘 / 可交互 | 400 ms / 800 ms | 发布构建，5,000 个请求工作区；启动网络和清理不阻塞首帧 |
| 请求标签切换 | 50 ms 内 | 保留草稿和旧响应，后台运行不干扰输入 |
| 流式对话 | 100 token/秒时每帧最多一次提交 | 长文本与工具事件并存，关闭块不反复解析 |
| 大 JSON 响应 | 10 MiB 首屏 1.5 s 内，无超过 200 ms 主线程任务 | 原生格式化与虚拟化；不得通过静默缩小正文实现达标 |
| 连续交互 | 掉帧率不高于 2%，无超过 50 ms 帧 | 报告刷新率，Linux 软件渲染单独列出；比较用同会话 A/B |

macOS 使用系统 WebKit 与 Seatbelt；Linux 使用 WebKitGTK，shell 沙箱依赖可用的 Bubblewrap；Windows 使用 WebView2，目前无 shell OS 沙箱，相关执行需明确询问。跨平台 UI 能构建不代表三个平台已经完成发行验收。

最低窗口为 980 × 680；键盘、缩放、减弱动效和屏幕阅读器路径必须能完成关键任务。状态不能只靠颜色；错误应说明影响和下一步，敏感操作不能仅以一个模糊“继续”按钮授权。

## 9. 如何判定一次交付

发布审阅以三条闭环及其失败、取消、越界、恢复分支为单位，不逐按钮打勾。自动测试证明契约或特定分支，真实 Webview、OS 沙箱、客户端联通和上游行为仍需对应环境证据。

优先复核：

- 请求/Flow 的历史、生产守卫、脚本变量与取消：`crates/spanbay-app/src/app/tests/{execution.rs,items.rs,environments.rs,secret_hosts.rs}`。
- 网关认证、协议转换与流失败：`crates/spanbay-llm/src/llm/gateway/tests.rs`、`fields_tests.rs`。
- 审批、工作区绑定、队列和文件日志：`crates/spanbay-app-agent/src/agent_service/tests/`。
- 同步预览、秘密和导入复核：`crates/spanbay-app-sync/src/sync/tests.rs`。
- 人工发布走查：[smoke checklist](smoke-checklist.md)；命令与隔离数据要求见[开发指南](../development.md)。

运行限制表由 `npm run check:docs` 对照代码常量检查；其余要求按上面的测试位置与走查收集证据。

当前已知差距包括 Cookie 以外的次要持久化失败的用户可见性，以及本机/外部副作用不能整体回滚。它们需要在变更审阅时明确接受或修复，不代表本文批准了未来排期。
