# 交互设计

设计者和实现者从这里查界面原则：视觉语言、状态归属、危险确认、焦点与不可信内容。颜色定义在 `tokens/tokens.json`，经 `crates/spanbay-desktop` 编译并在 `crates/spanbay-gpui/src/ui` 注入；离线原型见[`design/prototype/index.html`](design/prototype/index.html)。

色域与对比度由 `cargo xtask check-tokens` 检查，架构与文案由 `check-arch`、`check-i18n` 守卫。功能见[产品手册](product.md)，机制见[架构](architecture.md)，取舍见[决策记录](decisions.md)；冲突判断见 [`docs/README.md`](README.md)。

## 1. 五条依据

### 1.1 任务生命周期与当前视图分开

用户切到别的模块看日志、改配置或回消息时，正在跑的请求、流式回复、Mock、网关和后台进程照常运行；模块首次访问才挂载，之后只隐藏。停止按钮点名对象，如“停止请求”“停止网关”“停止全部运行”，只写“停止”会让用户猜停的是什么。退出前列出仍在运行的工作，由用户决定，绝不静默结束（§9.3）。

### 1.2 配置面与运行面分开

服务商、密钥、模型、备用链、环境、Mock 定义决定以后怎样执行；请求结果、网关日志、运行摘要记录这一次发生了什么。改配置不重写已有的运行记录，日志里的实际目标保持发出那一刻的值。运行视图也不替用户改配置：服务商测试结果要显式应用，环境里未保存的值不参与发送，保存 Mock 定义和启动监听是两个动作。

### 1.3 跨模块交接只带有限上下文

从失败响应、历史、网关日志或请求打开对话时，只生成带上下文的草稿：不调用模型、不发送、不授予权限，也不产生网络请求或改配置。用户先看到目标和携带的内容，再决定发送。上下文只带预览里看得见的部分，整段日志、密钥和工作区文件不会被悄悄塞进去。

### 1.4 危险动作按目标、范围、权限逐层确认

确认框说明目标、影响范围和实际权限。完全权限、文件夹信任、无沙箱运行是三个决定，各自确认，不合成一个“继续”。拒绝、取消、关闭视图是三件事：关掉审批面板只是离开视图，等待中的审批照样等用户回答。生产环境的发送确认按方法生效，一次确认覆盖整次运行。

### 1.5 密集数据靠结构，不靠删信息

大列表、大正文、长对话靠层级、对齐、虚拟化、窗口化和局部更新保持流畅，不为帧率隐藏风险、删掉键盘路径、裁掉正文或伪造截断状态。确实要截断时，告诉用户截断了什么、怎样看全；缓存失效和格式化失败同样要说出来。

## 2. 视觉语言

界面像一张安静的仪表台：底色退后，数据和状态站在前面，一屏只有一个强调色块，就是下一步要按的按钮。没有渐变、玻璃和纹理，一种东西只有一个实现。

### 2.1 表面、文字与选中

层级由窗口底、窗格、内容面、次级面、凹陷面、浮层依次表达。组件只用语义变量，不写颜色、间距或圆角的字面量。文字分正文、次级正文、元信息和停用四档；停用色只给停用态和非文字装饰。结构分隔用细线，输入框、复选框、开关的边界要达到非文字对比度。选中用主题色的前缘竖条、选中纸面与加粗，表格行用浅底加竖条；竖条只表示选中，深链到达用一次淡出的底色。

色彩主题提供八套低眩光护眼基底色板（靛蓝板岩、深海青岚、极光冰蓝、青瓷护眼、松石翠绿、暖砂护眼、星云靛紫、极简石墨），各自适配浅色纸面与深色模式。单一色板定义位于 `tokens/tokens.json`，由 `crates/spanbay-desktop` 在编译期嵌入并实时计算 OKLCH 语义色。

在任意色板内，用户可独立设定主题强调色（跟随色板、8 套 OKLCH 预设或自定义 `#RRGGBB`）。代码高亮支持 6 套浅/深成对配色（Catppuccin、Rosé Pine、Tokyo Night、GitHub Clean、One Pro、跟随色板）。经 `crates/spanbay-gpui/src/ui/syntax_theme.rs` 注入全局 `HighlightTheme` 后，可在「设置 › 外观」四分区工作台与标题栏快捷主题浮层单帧切换。

窗口外壳不是网页：除输入框、编辑器和代码外，界面文字默认不可选，双击标题不会选中单词。人们会复制的内容主动开启可选状态，包括响应与聊天正文（流式 Markdown）、日志与表格单元格、代码与差异、错误与提示文字、路径、版本、ID 和地址；区域里的按钮、标签页等控件仍是外壳。

窗口标题栏（`crates/spanbay-gpui/src/views/shell/chrome.rs`）在 macOS 上通过原生 GPUI `TitleBar` 提供拖拽区与系统红绿灯集成；按钮、输入框和标签页照常点击。

### 2.2 强调与状态

- 实心强调色只给主按钮和发送键，每个视图至多一个主按钮。开关、复选框、标签下划线、按下的筛选胶囊用墨色；链接和变量用强调文字色。运行中、保存中的指示用中性墨色。
- 状态同时用形状、词和颜色，颜色只是第三条线索：圆是正常，三角是警告，菱形是出错，空心圆是空闲，空心方是已取消。有终点的工作在运行时画开口弧，常驻服务在线时画带扩散环的实心圆。
- 健康是常态：正常与运行中的词用次级正文色，只有警告和出错的词带颜色；HTTP 状态码是数据，随色调着色。蓝点只表示未读，未保存与已更改用墨点，列表里的“已完成”不画标记。
- HTTP 方法只用文字色和等宽粗体，不填成芯片。被限流与无人应答的超时各有状态词，不记成“已拒绝”。

### 2.3 深度、圆角与动效

阴影分三层：页面卡片用浅描边加短阴影；菜单、弹出层、toast 与待批准卡浮起一层；对话框与遮罩抽屉最深并带遮罩。页内卡片只描边。圆角随层级同心递增，内圆角等于外圆角减去内边距；可点的胶囊用全圆角，只读标签用小圆角。动效只给用户能感知的状态变化：选中、浮层出现、新到达的行。只动底色、透明度和位移，曲线与时长由变量统一。命令面板和菜单开合没有动画，页面加载不做渐入。减弱动效时时长压到近零，转圈与脉冲停住，流式光标变成静态块。

### 2.4 字体缩放与中英排版

字号从一个界面字号变量推导，用户缩放只改它；断点用 em，调字号会让布局重排，条带、胶囊和窗格随之放大。中文界面自动加一档字号和行高。字重三档：常规给正文，中等给控件文字，粗体给标题、选中与数字；部分中文系统字体没有中等字重，层级不只靠中等对常规。

中文与拉丁字母之间加空格（`使用 Agent 循环`），数字与中文量词之间不加（`38个模型`）。等宽只给代码、ID、URL、路径与请求头，数字列右对齐。修饰键在 macOS 显示符号，其他平台写 `Ctrl`、`Shift`、`Alt`。默认语言 zh-CN，另有 en；用词以[术语表](reference/glossary.md)为准，文案的键、占位符和中英间距由 `cargo xtask check-i18n` 检查。

### 2.5 对比度与非颜色线索

正文与可读元信息对底色至少 4.5:1；非文字边界、焦点环、选中竖条和状态形状至少 3:1；浅色与深色主题都要满足。焦点环全局一种，在会裁切的容器里向内画。状态有形状和词，diff 行带 `+` 与 `−`，选中有竖条和字重，链接静止时带细下划线。强制颜色模式下靠描边与轮廓传达信息，不靠底色、阴影或渐变。停用只有一个配方并写明原因，不用半透明表示停用或“已关闭”。

### 2.6 宽度、折行与截断

宽度由容器决定。说明、提示、备注占满所在列，列本身才有上限；页面内容列有统一上限并随窗口收缩，对话列是唯一保留的阅读宽度。偏好行标签与说明在左、控件在右。表格把剩余宽度给名称类的列，数字、日期、状态、开关用装得下最长值的定宽列。

行文默认用 `text-wrap: pretty`，短标题用 `balance`。唯一的例外是设置页一到三行的辅助说明，也用 `balance`，因为中文末行常只剩两三个字。`text-wrap` 只是渐进增强，版面靠整宽规则成立。

省略号只用在列表行、窗格行、表格单元和标题栏，空间够时不截断；被截断的文字由壳层统一在悬停时补上完整的原生提示。路径与 URL 用中间省略并保留最后一段。行文不截断、不限行数，除非同一处有展开入口。

## 3. 信息架构与状态归属

### 3.1 壳层与模块

壳层是侧栏加一张页面卡片，卡片里是列表窗格、工作区和右栏。侧栏的目的地分 API 与 AI 两组，设置在页脚；一张注册表同时决定导航目的地、快捷键和命令面板条目，模块按需加载。

- 除请求与设置外，模块用同一种工作区头部：对象名、一个状态、少量副信息、次要按钮、至多一个主按钮和溢出菜单。窄宽下副信息先截断，次要按钮再收成图标，主按钮和对象名最后让位。
- 主按钮必须是“下一步”：运行中的服务没有主按钮，“停止”是次要按钮，停止后主按钮是“启动”。
- 进入模块时没有记住的选中就打开第一项；请求以标签会话为准，对话以上次打开的为准。选中的对象被删后选中移到下一项；对象在别处消失时工作区显示缺失提示。筛选和刷新保留选中。新建即时创建并进入就地改名，对话框只用于要选位置的新建。

跨模块跳转分“查看”和“派生”两类，规则见[产品手册 §1](product.md#在模块之间交接)。落点首条条带显示“返回 {来源}”；Esc 不做跨模块返回，设置是唯一例外。深链落空时，落点用内联的缺失提示写明对象类型与名称，不弹对话框或 toast。

设置页的原则：一个事实只在一页出现，也只有一个编辑入口；设置页只放偏好和访问权限，服务商、价格、用量各有主人页。页首面包屑的当前项就是唯一的一级标题，内容区不重复页名。区说明至多一句，只写行里没有的信息。正常状态不加标签，不正常时才出现警告色的文字标签。

- 控件与数据类型对应：只读信息不做成设置行，能就地改的不弹对话框；没有功能的控件不露面。去别处的入口是相关行下方的一行普通链接，同类入口每页至多一处。
- 每个列表都有加载、失败、空三种状态：加载画骨架，失败写原因加“重试”，空状态写一句话加一个动作。

### 3.2 状态归属

| 状态 | 归谁 | 保存在哪 |
| --- | --- | --- |
| 工作区、集合、请求、环境、历史、Cookie、证书、Mock、流程 | Rust 核心 | 主数据库 |
| 服务商、网关规则与客户端、调用日志、对话与消息、设置 | Rust 核心 | 主数据库 |
| 秘密值 | Rust 核心 | 主库旁的明文 SQLite 保险库，只有同一系统用户可读 |
| 附件、编辑前快照、完整工具输出、客户端配置备份、日志 | Rust 核心 | 数据目录下的文件 |
| 壳层布局：导航、分栏、面板宽度、设置导航 | 前端壳层 | 本机存储，所有工作区共用 |
| 模块里的选中、标签页、布局 | 各模块 | 本机存储，按工作区分开 |
| 请求标签草稿 | 请求模块 | 核心按工作区存库 |
| 对话输入草稿 | 对话模块 | 本机存储，有大小与保留期上限 |
| 表单草稿与保存中状态 | 各模块 | 只在本次运行，切页与退出前写出 |
| 监听器、连接、审批、进程、回放、响应句柄 | Rust 核心 | 只在进程内；重载页面不停它们，进程退出就结束 |
| 演示数据 | 演示适配器 | 内存，刷新回到种子 |

业务内容不写进本机存储的界面状态。常规读取不返回秘密，敏感输入只在提交时短暂持有。日志与捕获按已知字段和已存的值脱敏，认不出任意正文里陌生的短秘密。视图层不直接访问存储或底层异步运行时，统一经 `crates/spanbay-desktop` 与 `crates/spanbay-gpui/src/bridge` 调用核心。标签会话能恢复编辑，恢复不了实时响应；历史记下发过什么，完整正文可能已被清理。

### 3.3 对话模块的信息归属

同一件事在同一时刻只有一个说话的位置，其他位置只是指向它的入口。

| 信息 | 唯一位置 | 其他位置只做什么 |
| --- | --- | --- |
| 现在在做什么 | 输入框上方的 StatusLine，运行中 | 过程块标题只写步数与计时 |
| 需要你做什么 | 关卡区第一张卡 | 线程标记行、列表行状态句、侧栏计数、头部角标 |
| 工具失败 | 线程里那一行，默认收起 | 过程块头的“N项失败” |
| 改动行数 | 编辑行，整文件口径 | 面板“改动”页与回合末改动条同口径 |
| 计划 | 线程里的计划块 | 面板“进展”显示进度 |
| 权限与计划状态 | 底栏的模式芯片 | 面板“设置”只放此对话的例外 |
| 待发与暂停 | 输入框上方的待发列表与暂停条 | 无 |
| 工作区与环境 | 头部绑定芯片 | 起始页上下文行；失败行的下一步按钮 |

发送之后，线程立刻在用户消息下画一行“思考中…”，直到模型的第一个思考、文字或工具事件到达，这一行就被它们顶替。这一行只有字形和这个词，模型名与计时仍只在 StatusLine 里说。思考内容边到边显示，思考结束后收成“思考了 N 秒”；文字同样边到边显示。

详情栏打开时，列表窗格在宽档也收成遮罩；工作区宽不足 80 em 时详情栏浮动，字号越大越早浮动。头部宽不足 62 em 时，工作区、环境与项目文件夹收成一个“上下文”按钮，未绑定时它仍写行动词。列表窗格让位时，头部的列表开关带“需要你”角标。

## 4. 图标

唯一的图标集是 Lucide，只从 `crates/spanbay-gpui/src/ui/icons.rs` 的图标表引用。一个概念一个字形，动词用文字写出来，主操作永远有可见的文字标签。同一条头部里不放同形异义的图标。

- 图标按钮只用于通用字形（关闭、复制、更多、搜索、加号、发送、停止、刷新、面板开关等），每个都有可访问名、延迟出现的提示和足够的触达面积。
- 列表与表格里的状态用状态标记；Lucide 的状态字形只留在 toast 与横幅里，“信息”用 info 字形。“停止”动作用实心方块，“已取消”状态用空心方。
- 不用图标字体、emoji、位图或彩色图标（状态色与选中的导航除外）。去设置页的链接统一写成文字加箭头。折叠侧栏后的图标窄轨把文字留作可访问名和悬停提示。

## 5. 组件边界

全仓仅 `crates/spanbay-gpui/src/ui` 允许引入 `gpui_kit::component` 并封装语义原语，业务模块视图留在 `crates/spanbay-gpui/src/views`。每个原语只读 OKLCH 编译后的语义色板。边界按行为分；层叠类的焦点与 Esc 见 §7，长内容见 §10，破坏动作见 §9.3。

- 编辑类（输入框、文本域、数字框）保留光标、选区、输入法组合与撤销，错误挂在字段下，长文本自动增高。
- 选择类（选择器、菜单、命令面板、模型选择器）外观像输入框、列表是浮层，支持方向键、首字跳转和 Esc，不用原生下拉弹窗。所有选模型的地方共用一个模型选择器。
- 表格只有只读数据表和可编辑键值表两种。键值表末尾总有一行空白新行；窄容器下键在上、值在下；粘贴多行文本拆成多行。
- 响应与报文查看统一复用 `crates/spanbay-gpui/src/ui/payload_viewer.rs`（`PayloadViewer` 与 `payload_block`）。组件自动识别 `JSON / XML / HTML / YAML / Text / Diff`，提供格式化与原文切换、自动换行、语法高亮和一键复制，覆盖全部工作模块。

按钮标签是动词加名词，会弹确认或还要再输入的按钮带“…”。停止类按钮点名对象，两个停止不同排；危险样式只给真正危险的动作。分段控件用于同一对象的视图或模式；标签页是唯一的标签样式。对话框里只有主按钮和单行输入框里的 Enter 两条提交路径，失焦不提交。主按钮要么可点并把错误标到字段上，要么写明还缺什么；提交中对话框保持打开，成功才关闭。

跨多次调用的合计只在用量与日志模块显示。其他模块不画用量图、不算区间合计，需要时放“查看用量”链接，带上筛选与时间范围跳过去；单次调用自带的用量留在原处。需要时间范围的视图用预设的滚动窗口加解析后的具体时间。

## 6. 状态、空态与反馈

状态词各有原因，不混成一个“失败”：等待批准、需要你、运行中、完成、阻塞、被限流、超时未运行、已跳过、已取消、过期。对话里命令审批写“等待批准”，计划写“等待确认”，提问写“等待回答”；工具失败写“未能”加动词，命令非零退出另带“退出码 N”，信号终止、超时与取消没有退出码。异步数据按读取状态画界面：

- 第一次读取中稍等片刻再画骨架，不显示“0 个”或“先添加一个”。还没开始读时什么都不画。
- 读到了但为空：一句事实加一个下一步动作。首次使用给新建；无结果复述查询和筛选范围，动作是“清除筛选”。
- 从没读到过就失败：错误占位写清哪里失败、为什么、怎么办，带“重试”和可复制的技术细节。错误从不画成空态。
- 有数据时失败：保留数据，加一条“数据可能过期 · 重试”横幅；刷新中不清空。离线是失败的一种。
- 确认框写“没有引用”“0 把密钥”之前，对应数据必须真的读到了。

错误只有三个出口：字段错误挂在字段下，与一块内容绑定的说明用内联消息，整块读失败用错误占位。横幅和 toast 不承接校验错误。核心返回英文原句或内部 ID 时，界面显示本地化的一句话，原文放进技术细节。取消类错误不弹错误提示，带稳定错误码的原因（工作区不存在、数据库忙、磁盘已满、无权访问等）显示本地化句子，其余显示核心说明。

| 通道 | 何时用 | 规则 |
| --- | --- | --- |
| 行内 | 结果就在操作处可见 | 优先用它；复制成功时按钮短暂变成勾并播报 |
| toast | 结果不在视线里，或带撤销 | 条数有上限；成功自动消失，带撤销的停留更久，错误不自动消失 |
| 横幅 | 影响整个模块的持续状态 | 同屏至多两条，其余折叠成“+N”；要么可关，要么写明何时消失 |
| 侧栏徽标与“需要你” | 后台工作与等用户的事 | “需要你”只算人类关卡：批准、回答、批准计划、费用上限，不含未保存的编辑与“队列已暂停” |
| Dock 徽标与系统通知 | 窗口不在前台且有事卡住 | 通知由 Rust 侧发出，总开关是 `general.notify_when_away` |

- 系统通知同一对话短时间内合并，正文只写类别（“等待批准：运行命令”），不写命令文字或秘密；点击后窗口到前台并打开那个对话。
- toast 不报已有行内指示的事，横幅里不放主色按钮。复制在写入真的完成后才报成功，失败用 toast 说明原因。禁用的控件在提示与可访问描述里写明原因，或保持可点、点击时说明。
- 模型目录同步不用对话框：页头显示进行中、结果摘要和错误条。失败时用当前语言说明原因，给出最近一次成功同步的时间，并写明仍在用旧数据。

## 7. 焦点、键盘与 Escape

最上层控制键盘：打开的层之下收不到快捷键。命令面板打开时只有它自己的键有效；模态对话框或模态抽屉打开时全局命令暂停，会关闭窗口的组合仍被拦住；弹出层、菜单或遮罩窗格打开时，导航类快捷键先关掉这一层再执行。

Escape 归最上层、最内层，不按组件种类排全局优先级：对话框里的弹出层先关弹出层；键值表的内联面板先于外层对话框；设置行里的就地编辑先撤销这一行，再离开设置。没有可关的层时，Esc 不触发全局命令。Esc 先过输入法守卫，组合输入期间不关闭、不提交、不触发命令。

- 模态对话框与遮罩抽屉困住焦点，关闭后回到打开者；停靠的抽屉不困焦点。弹出层与菜单关闭时还焦点给触发器，用户已把焦点移走就不拉回。
- 遮罩窗格是工作区内的模态：工作区不可交互，侧栏仍可达；模块隐藏时关掉自己的遮罩。
- 对话框提交后焦点回打开者，打开者已被删除时回到列表的当前行。从弹出层打开对话框前，先关弹出层并把焦点放回它的触发器。
- 切模块时焦点交给新模块的工作区。控件变形（发送与停止）在原位换内容，焦点不丢。删除当前行后焦点到下一行；清空列表后焦点到空态的动作；审批卡被回答后焦点回输入框。
- 自动取焦点只在焦点位于页面本身、工作区容器或空的已聚焦输入框时发生，否则只播报。用户明确要去某张卡时（点通知、点“需要你”里的一行）无条件给它焦点；隐藏模块里不取焦点。被取焦点的元素必须可见。

对话发送区的键位：

| 状态 | ↵ | ⌘↵ |
| --- | --- | --- |
| 空闲 | 发送 | 发送 |
| 运行中且有文字 | 排队 | 引导 |
| 审批在等 | 排队 | 无动作 |
| 计划或提问在等 | 继续计划或回答 | 同左 |
| 空闲且队列已暂停 | 直接发送 | 直接发送 |

⇧⌘↵ 停止并发送，⌘. 停止当前运行，⌘⇧P 模式菜单，⌘⇧O 轮换模式，⌘⇧M 模型菜单，⌃O 展开或收起本对话的全部步骤；Shift+Tab 始终是反向焦点。卡有焦点时 Esc 只归卡（拒绝、跳过、继续计划）；输入框有焦点、没有弹层、不在输入法组合中时，1.5 秒内连按两次 Esc 才停止运行。

在对话内按 ⌘⇧A 开关 90% 视口工作流模态框，其余模块按 ⌘⇧A 直达左侧独立的全局「运行看板」模块。智能体工作流与 HTTP 流程共用同一套 ProcessView 视觉语法，包含步骤 / 执行图 / 时间轴切换、横排 / 竖排 / 折行、泳道分组、对齐、拖拽调位与一键重置排版及右侧滑出节点检查器。两者领域与作用域保持隔离：流程历史留在流程顶栏，全局运行看板专注智能体运行，集合运行保留为批量矩阵标签。Esc 逐层关闭。

键盘路径：Tab 顺序跟随 DOM。文本输入框里只响应带修饰键的组合，不用裸 Alt+字母，因为 macOS 上它会输入字符。窗格列表同一套键：↑↓、Home/End、Enter 打开、F2 改名、Delete 与 ⌘⌫ 删除、Alt+↑↓ 重排、⇧F10 行菜单、首字跳转、⌘F 搜索。F6 在壳层区域之间循环，区域不嵌套。每个拖拽都有键盘等价，拖动中 Esc 取消，落下后可以撤销。⌘Z 在可编辑元素里是文本撤销，其余地方撤销最近一次删除。快捷键提示都从注册表取。

语义与读屏：集合树用 `tree`，平铺列表用 `listbox`，可编辑表用 `grid`，对话线程与日志用 `log`，危险与花钱的确认用 `alertdialog`，运行状态用 `status`。菜单项是按钮，不用链接冒充按钮。流式节点不进 live region，只播报阶段变化，同一状态变化至多播报一次。交互目标有最小触达面积，图形更小时用透明扩区补足。

## 8. 不可信内容

Webview 只经 IPC 与核心通信。生产 CSP 只允许本地资源和 IPC 连接，禁止内联样式和内联脚本，Webview 自己不发外部网络请求。模型输出、MCP 结果、导入内容和网络响应在界面里都按数据显示。

- 标记里没有内联样式，数据驱动的尺寸只经一个几何模块写 CSS 变量。不用 `eval`、`new Function`、`srcdoc`，也不把 HTML 字符串插进 DOM。附件与缩略图经 IPC 取原始字节，再转成 `data:` URL。
- Markdown 渲染成 React 树。远程图片不加载，显示为带主机名的链接；链接只认 `http:`、`https:`、`mailto:`，由核心再校验后在系统浏览器打开。
- 剪贴板写入只发生在用户显式的动作上。导入内容先预览再应用；不可信的 HTML、脚本和 MCP 配置不直接执行。
- 秘密在界面上的显示规则见[产品手册 §1](product.md#哪些会保存哪些只在当前进程存在)。层间隔离与视图边界规则由 `cargo xtask check-arch` 在真实源码上检查。

## 9. 草稿、保存、撤销与危险操作

### 9.1 四类保存语义

| 类 | 适用 | 何时写入 | 失败与离开 |
| --- | --- | --- | --- |
| 文档型，带草稿持久化 | 请求标签 | ⌘S 或保存按钮；未保存的编辑按工作区存着 | 离开、切工作区、退出不问；关闭有未保存更改的标签时问 |
| 文档型，不带草稿持久化 | 环境、集合设置、目录模型抽屉 | ⌘S 或保存按钮；未保存的值不参与执行 | 离开、切工作区、退出都问：保存、不保存、取消 |
| 配置记录型 | Mock 服务、流程、服务商配置、网关客户端 | 停止输入后自动保存 | 失败保留草稿，显示错误与重试；离开时有没存上的才问 |
| 字段型 | 设置 | 开关与分段立即写，文本在失焦或 Enter 时写 | 立即控件失败即回退；文本保留错误草稿，离开时回退并提示 |

保存失败一律保留用户的编辑，迟到的响应不覆盖更新的草稿。切页、页面隐藏和退出前写出全部草稿。保存状态只有一个指示，在工作区头部尾侧：未保存的更改、正在保存（写入稍久才出现）、已保存、出错加重试；只播报成功与出错。对话框里尚未提交的输入不算未保存的更改。

### 9.2 撤销

可还原就撤销，不可还原才确认，同一个动作不既确认又撤销。

- 能还原的删除（请求、集合、Mock 服务、环境、历史等）不确认，toast 写出对象名并带“撤销”。没有撤销的操作，确认文案写明“不能撤销”。
- 撤销只有一个槽：焦点不在输入框时，⌘Z 执行屏幕上最新的那条撤销。对象不在当前模块时，恢复后提示“前往”，不自动跳转。切换工作区时旧工作区的撤销随之失效。
- 还原只用核心的可恢复删除或删除前取到的整条对象，不拿列表里的摘要行回写。撤销失败要报出来且不自动消失，部分恢复时写明哪几项没恢复。
- 运行中的对话先确认，等运行停下再删除；关闭确认框既不停止也不删除。

### 9.3 危险操作

| 确认类型 | 例子 | 默认焦点 | 正文 |
| --- | --- | --- | --- |
| 普通 | 应用导入、退出并停止服务 | 确认 | 说明会发生什么 |
| 危险，不可还原 | 删除服务商、清空历史、删除工作区、停止并退出 | 取消 | 写后果和“不能撤销” |
| 花钱 | 基准测试、测试全部模型 | 取消 | 写估价与依据，按钮带金额 |
| 三选一 | 关闭有未保存更改的标签、离开环境 | 保存 | 写对象名，按钮顺序全应用一致 |

永不静默的动作：删除含秘密的条目、覆盖式导入、丢弃未保存的更改、停止有副作用的运行、花钱的调用。

- 退出：退出请求都被接住，macOS 上是 ⌘Q、应用菜单与菜单栏图标的“退出”，Linux 与 Windows 上是关窗。macOS 的红灯只隐藏窗口，常驻服务继续运行，Dock 图标或菜单栏图标把窗口带回。依次收起命令面板与弹出层，逐个询问未保存的文档，确认停止运行中的工作，在有限时间内写出草稿，最后关窗。会丢失工作时用危险确认，只有常驻服务（Mock、网关、MCP）在跑时用普通确认。草稿没写出时列一次，可选“留下”或“仍然退出”。任何一步取消，什么都不发生。
- 切换工作区与退出同一顺序：先问未保存的文档，再确认停止运行中的流程与集合运行，再写出草稿，最后切换。
- 完全权限：危险对话框，必须勾选“我已了解”，默认焦点在取消。硬阻止、规则 Block、强制询问和可用的沙箱照样生效，见[架构 §11.2](architecture.md#112-审批与沙箱)。文件夹信任和无沙箱运行与它分开确认。
- 生产环境发送：只对需要确认的方法生效，环境可以把确认扩大到安全方法。一次确认覆盖整次运行，预请求脚本改了方法会重新检查，脚本里发出的子请求不受这道确认管。
- Mock 端口与路径前缀改后要停止再启动才生效，其他路由与响应配置即时生效。
- 带秘密导出：普通目录可以直接选，版本库、云同步、共享目录要输入确认短语。导出文件是明文，只有本机用户可读，进了版本历史或云备份就收不回。界面如实称它明文导出，也不说成“公开”。

### 9.4 取消与部分结果

取消不回滚。请求历史与 Cookie 不在同一事务；流程每次实际发出的尝试都写一条历史，但不写响应 Cookie；脚本写入的变量会保存。停止后不发起新的尝试，已完成的步骤、变量修改和远端副作用都保留。取消后的状态写成“已取消 · 已发出 N 个请求”，后半句不能省，否则像什么都没发生。对话的终态行写“已取消 · 运行了 {time}”，接已发出的请求、已运行的命令与已编辑的文件数，一项都没有时写“没有发出请求，没有改动文件”。

## 10. 连续任务、窄屏与长内容

布局档位按应用宽度除以界面字号得到 em，字号越大越早进入窄档。最小窗口见 [PRD](product/PRD.md)；在最小窗口加最大界面字号下，每个模块的主动作都要能做完：发送并看到状态码、保存、运行、停止、批准、回答。

- 窄档时，模块列表窗格与设置导航用同一种遮罩，由工作区首条条带开头的“显示列表”打开；右栏也是遮罩。
- 侧栏只在用户点折叠按钮或按 ⌘B 时切换形态，选择跨启动保留；窗口宽度、打开设置、切换模块都不改变它。
- 分割的工作区（请求与响应、流程步骤与结果、对话线程与右栏）在窄档能把一侧铺满，再按一次或 Esc 还原。
- 工具条的主动作最后收起，收进溢出菜单的项保留快捷键。带动作的状态卡放在可滚动区里，动作行总能滚到。
- 窄档下 toast 只展开一条，不盖住主动作。对话的关卡区最高占对话列高的 45%，超出在区内滚动；卡放不下时收成一行摘要（命令仍须展开后才能允许），输入框至少留两行。StatusLine 恒为一行，有关卡时左侧留空，本身不是 live region。浮动的详情栏遇到新关卡先关闭一次并把焦点交给关卡卡，栏内有弹窗时在栏顶显示“回到对话”横幅。对话框头尾固定、正文滚动。

流式内容贴着底部时跟随增长，用户向上滚就解除跟随并出现“跳到最新”；流结束后焦点不动。高频事件先进 store、按帧提交，回放过期时改读持久化的快照。审批、提问、计划和费用暂停这类卡片放在线程下方的关卡区，不随线程滚走；多张待处理时只让第一张取焦点，刚出现的片刻内忽略按键，点击立即生效。

长内容：大正文有预览与句柄，默认不把全量正文放进 React 状态，复制和格式化走完整内容。代码查看器只挂载可见行，长行先截断再提供“显示全部”，超出高亮上限时暂停高亮并提示。集合树、网关日志和历史用虚拟列表，行高随密度与字号重读。Markdown 按块增量解析，已闭合的块直接复用。长 URL、请求头和路径换行或横向滚动，不裁掉信息。

## 11. 无头集成测试与真实桌面运行时各能验证什么

| 运行形态 | 组成 | 能验证 | 验证不了 |
| --- | --- | --- | --- |
| 无头测试（`test-support`） | 真实 GPUI 视图树加内存 `DesktopRuntime` | 9 模块挂载、16 套 OKLCH 主题热切、20 页设置、命令面板、10k 虚拟表与 10 MiB JSON Rope 载入 | 真实 OS 窗口合成帧率、真实文件对话框、系统托盘与签名沙箱 |
| 发布构建（`spanbay`） | 真实 GPUI Metal/Vulkan 窗口、Rust 核心与本地数据 | 功能、持久化、权限、沙箱、端口、真实启动与空闲内存、平台行为 | 跨机器绝对毫秒比较 |

原生组件与压测工作台同时内置于应用「控制台」实用工具中，方便在真实 GPU 窗口下人工核对中文 IME 候选框跟随、流式 Markdown 划选复制与 120fps 滚动。

## 12. 验收

| 原则 | 检查什么 |
| --- | --- |
| 任务与视图分开 | 切模块不卸载、不停止；退出确认列出运行中的工作；停止按钮点名对象 |
| 配置与运行分开 | 环境里未保存的值不参与发送；Mock 保存与启动分开；服务商测试要显式应用 |
| 交接只带有限上下文 | 打开交接只生成草稿；上下文预览可见；发送前不调用模型 |
| 危险动作逐层确认 | 完全权限、文件夹信任、无沙箱分开确认；生产确认按方法；拒绝与关闭视图是两件事 |
| 密集数据不删信息 | 长内容虚拟化或窗口化；截断与失败有提示；键盘路径可见 |
| 视觉与键盘 | 一屏一个强调色块；状态有形状和词；最上层控制键盘，关闭后焦点回到触发处 |
| 宽度与折行 | 窄宽与两种语言下没有无省略号的硬裁切，省略处有悬停提示 |

常用命令：`cargo xtask check-arch`、`cargo xtask check-tokens`、`cargo xtask check-i18n`、`cargo test -p spanbay-gpui --features test-support --locked`。绝对毫秒数、测试数量与打包字节不作为设计规则，它们随机器与构建变化。
