# 需要继续维护的决策

每条决策写五件事：约束、选择、理由、代价、何时重议。行为验收由 [PRD](product/PRD.md) 负责，机制由[架构](architecture.md)负责，这里只记取舍。

旧编号仍有源码引用，§12 给出可检索语义。被推翻的决策在原位第一行写“已被 D-nnn 取代”。新决策从 §22、D-262 起追加，一条一个编号。

## 1. 本机拥有工作数据，但不宣传离线或加密

- **约束。** API 工作内容、密钥和代码属于用户，日常编辑不需要云账号；用户主动调用的服务商和工具仍要联网。
- **选择。** 业务元数据落本机主库，凭据放进附着在主库旁的独立保险库，内容字节放文件系统；界面偏好和 Chat 输入草稿留在 Webview 本机存储。未修改的秘密保留，空串清除，新值替换（D-121）。
- **理由。** 用户不依赖服务端账号就能维护工作台；秘密与普通库分开，能减少复制主库时的泄漏，但这不叫加密。
- **代价。** 保险库是明文 SQLite，文件权限挡不住同机的恶意程序；正文和附件也可能含凭据。主库、保险库和内容文件不能靠复制一个文件做一致备份，也没有跨库崩溃原子性。
- **何时重议。** 要做系统凭据保护、完整备份或多用户隔离时，先设计密钥生命周期、一致性和失败恢复，不只改文案。

## 2. 共享请求管线，显式区分执行证据与外部副作用

- **约束。** Send、Runner、Flow 和原生请求工具不能各写一套认证、脚本、重试与变量语义；多步执行也给不了网络事务。
- **选择。** HTTP 调用共用一条执行管线，入口决定历史与 Cookie 策略：Flow 写每次尝试的历史，不写响应 Cookie。AI 服务商目标另走 AI 用例，在脚本之后锁定目标与凭据（D-200、W-04、W-16）。
- **理由。** 修一处执行语义就覆盖所有入口，同时保留 Flow 防 Cookie 污染、按运行追踪的要求；历史按来源和运行 ID 解释每次尝试，一个“通过”吞不掉中间失败。
- **代价。** 脚本分阶段提交变量，历史与 Cookie 不同事务，取消不回滚已提交数据和已发请求。历史没写成时响应旁会标明，其余持久化失败只记诊断，够不上可靠审计。生产确认只守实际要求保护的方法，脚本 `pm.sendRequest` 受同一守卫。
- **何时重议。** 要可恢复工作流、可靠审计或补偿操作时，设计运行账本与可见的保存失败，不用包住网络调用的长事务。

## 3. 服务商“被识别”和模型“可用”分别取证

- **约束。** 兼容端点、密钥被接受、模型能回答、能力可靠是四件事；探测本身要花网络和费用。
- **选择。** 预设与目录只预填，发现结果带证据；用户显式添加服务商，再跑真实探测并复核 Apply。没观察到的能力不记为不支持；探测结果怎样进入路由见 D-276（D-41、D-42、D-43、D-44、D-203、D-205）。
- **理由。** 能解释部分成功、限流与样本的不确定，不让一次错判把本来可用的目标永久排除。
- **代价。** 结果随时刻、密钥、模型和样本变化，一个绿格不是 SLA；空体路由探测可能被宽松端点当补全执行，费用不一定为零。
- **何时重议。** 需要长期健康监测或自动调度时，另行设计样本、过期、成本和用户授权，不把手动测试扩成后台监控。

## 4. 运行与观察者分开，重载不取消，重启不假装续跑

- **约束。** 切换模块和重载 Webview 是正常事件，不能杀掉已批准的任务；应用崩溃后没有内存里的运行可以恢复。
- **选择。** 核心持有智能体注册表、取消与有限回放，视图只订阅。页面代际退休旧 sink，重连从快照与回放恢复；进程重启把未完成运行标为中断，并结算进程账本和文件日志（V-4、C-04、W-15）。
- **理由。** 执行所有权稳定，界面可以重建；观察者数量能反映有没有人在处理审批，死 Channel 不会让无人值守的审批永远等待。
- **代价。** 回放会过期，增量会合并，界面要处理缺口、序号区间和运行换源。崩溃修复只依据持久事实，恢复不了实时正文和外部副作用。
- **何时重议。** 要跨进程续跑或支持多个可独立控制的窗口时，重设命令幂等、所有权和持久运行协议，不靠扩大回放环冒充持久调度。

## 5. 智能体权限、沙箱与可复核写入

- **约束。** 模型和返回内容都可能不可信；单次审批、长期规则和 OS 隔离解决不同问题，实际工具链还得能在受限环境里工作。
- **选择。** 硬阻止与强制询问优先于记住的 Allow 和模式默认，评估顺序见 D-274；Full access 只跳过普通逐次询问，保留沙箱与硬约束；无沙箱运行按会话单独确认并留记录（D-145、D-223、C-03）。审批等待时前台不超时，无人值守按限制表结束，拒绝或超时都返回未执行（D-119）。运行预算只在 [PRD 规范表](product/PRD.md#run-limits-normative)维护。
- **理由。** 用户看得懂自己授权了哪件事，一条 argv 规则不会间接放开任意复合命令；显式无沙箱选项给工具链留出口，不冒充同等安全。
- **代价。** macOS Seatbelt、Linux Bubblewrap 与 Windows 能力不等价，命令规则只是尽力而为；文件工具仍有路径竞争，MCP stdio 不在 Chat shell 沙箱内。文件写入先记原始字节与日志，逐文件撤销冲突时要求复核，没有整轮磁盘回滚。
- **何时重议。** OS 沙箱接口变化、要把 MCP 纳入隔离或要求整轮回退时，拿真实平台证据重设边界，不拿命令黑名单补沙箱。

## 6. 网关优先保真，跨协议转换必须暴露损失

- **约束。** 调用方使用多种协议，同协议客户端依赖未知字段、缓存前缀和字节形态；共同消息模型表达不了供应商的全部特性。
- **选择。** 同协议直通保留原字节，只改必要字段；跨协议经 hub 映射，带说明丢弃或拒绝。首个内容事件前可以故障转移，之后锁定目标。默认只听 loopback，先验 Host 与 Origin，LAN 与额外主机要求客户端令牌（D-270）；令牌轮换无宽限期，自动连接的令牌不经 Webview（D-193、D-199）。
- **理由。** 不为通用模型牺牲同协议保真，也不把两家模型的输出拼成一个看似成功的回答；转换说明、实际目标和尝试都属于调用结果。
- **代价。** 跨协议有损，缓存、推理、原生工具不保证等价；同协议响应里的模型名可能是上游名。日志队列有界，拥塞时丢捕获并计数；金额分币种，按本地日历日汇总，日志不是账单（D-122、D-198）。目录与价格见 §16。
- **何时重议。** 要支持新的供应商特性、公网部署、可靠财务账本或令牌宽限期时，分别审阅协议、安全和一致性，不加泛化开关。

## 7. 配置只有明确的写入入口，安全敏感值不借同步传播

- **约束。** 多处配置表单会产生不同的校验和草稿；远端文件不能替用户信任命令、扩大监听范围或泄露密钥。
- **选择。** Settings 管全局配置，模块管操作与观察；添加服务商、Apply 测试、连接客户端、会话覆盖是明确例外。设置先校验、持久化，再发布快照；深链定位唯一编辑页（D-13、D-221、D-234）。同步保留本机路径、信任和扩大暴露面的字段，秘密默认导出为占位符，客户端令牌与 TLS 口令不导出（D-223、D-228、D-230）。
- **理由。** 用户知道一次操作写了哪类数据，导入配置不会悄悄增加本机执行或网络暴露能力。
- **代价。** 共享了配置，对方机器也未必能立即执行：缺密钥、缺目录、MCP 待复核、模型重关联都是正常的导入结果，要用户补齐。
- **何时重议。** 扩充同步对象或增加自动启动能力时，先回答哪些字段可以跨机器授权，再扩序列化结构。

## 8. 文件夹同步采用可预览的实体胜负，不做协作合并

- **约束。** 用户经 Git 或云盘搬运配置，目录里会有冲突标记、交错写入、缺文件和不同机器的时钟。
- **选择。** `spanbay-app-sync` 先整体验证已知文件，坏文件不当删除。内容不同时按时间戳定默认胜负，时间相同时传入方胜出，用户可以改选；删除要显式开启，导入按实体应用并逐项报告；自动导出前先查外部待导入变化，有就停。
- **理由。** 小型可读的配置适合人工复核，不需要同步服务，也不会把陌生配置自动提升为本机权限。
- **代价。** 单文件原子改名不是全目录事务，逐实体导入可能部分成功；时间戳不是因果，预览也锁不住外部目录。失败后要重新预览。
- **何时重议。** 要实时双向、多用户并发或可靠删除传播时，引入版本与冲突协议，不再堆时间戳特例。

## 9. 视图不拥有后台工作，高频状态按局部订阅传播

- **约束。** 用户边看流式输出边编辑请求，隐藏模块也可能在跑任务；全局 React 状态会放大输入延迟。
- **选择。** 模块首次访问后保留挂载，用 hidden 与 inert 隐藏；store 继续收事件，隐藏视图暂停订阅（FE-R18）。选择器返回稳定引用或给相等比较，高频事件按帧批处理；Markdown 闭合块复用，长列表与长响应虚拟化（FE-R5、FE-R21、FE-R23）。
- **理由。** 任务不依赖页面存在，一次操作只更新相关订阅者，流式增量不扩散到整个工作台。
- **代价。** 要管理缓存、事件缺口、选择器引用与可见性恢复；虚拟行尺寸跟字号和密度走，不能写死。安全 Markdown 只输出树，不执行原始 HTML。
- **何时重议。** 数据规模或流事件模型超出现有缓存与虚拟化能力时，按剖析证据换方案，不为省几行代码引入全局重渲染。

## 10. 性能证据与依赖预算分开管理

- **约束。** 桌面 Webview 的输入与渲染预算有限；绝对耗时受机器负载影响，包体大小可以确定复算。
- **选择。** 复用已有的界面、状态、虚拟化与解析设施，简单需求不加依赖（D-60）。性能目标用发布构建与注明条件的同会话实测报告（D-61）。原 Web 时代曾按包体账本约束 JS 闭包，迁移至纯 Rust GPUI 后已由二进制体积与零 WebView 内存基线取代（D-243）。
- **理由。** 依赖和启动闭包的长期成本能算出来；跨时段的机器抖动不算代码回归，包小也替代不了真实交互测量。
- **代价。** 手写解析器与高亮器有范围限制，要维护夹具；性能报告和真实平台走查不能全靠 CI 数值。
- **何时重议。** 新的核心场景确有必要且有实测成本时，审阅计量范围和收益，不悄悄扩大阈值。

## 11. 桌面能力最小化，不把 CSP 当后端沙箱

- **约束。** 响应和模型内容可能被攻击者控制；Webview 不该任意执行代码、读写文件或直接发业务网络请求。
- **选择。** 外部能力只经受控适配层与核心；早期 Webview 壳通过固定 CSP 与受控字节预览限制能力，迁移至纯 Rust GPUI 后进程内零 IPC 直调仍经过核心路径授权与权限边界校验（D-246、D-247）。
- **理由。** Webview 的能力表可审计，路径、凭据与目标始终在核心手里；局部预览需求不靠放宽全局 CSP 解决。
- **代价。** HTML 预览的脚本与内联样式受限，复杂富渲染接不进来；CSP 管不到核心、shell 和 MCP 的网络外发。
- **何时重议。** 需要新原生能力或富渲染时，按威胁模型和具体入口设计，再改契约与测试。

## 13. 重议和证据纪律

- 改一条决策，审阅者至少回答：约束变没变、谁的可观察行为会变、已有数据与授权怎样处理、失败后怎样恢复。加一个字段或过一个测试本身不构成理由。
- 决策编号不表示优先级或排期。测试通过数和代码行数说明不了设计成立；截图只用于设计对照，真实平台的行为验收另行进行。
- PRD 运行限制表由 `cargo xtask check-docs` 对照智能体的限制常量检查。次要持久化失败的可见性、跨文件副作用等已知差距由 PRD 维护，审阅时要么明确接受，要么修实现。

## 14. 设置页按“一个事实一个主人”分页，跳转单向

- 网关访问一页已被 D-277 取代，搬到服务商 › 网关；其余仍有效。
- **约束。** 同一事实出现在两页，用户会改错地方；页面互相链接会成环，用户回不到起点。
- **选择。** 常规页与 AI 页都按“一个事实只出现一次、没有功能的控件不露面”整理（D-251、D-252）。AI 部分分「智能体」与「模型服务」两组，内置工具、MCP 服务器、权限各一页（D-255）。设置页不链功能模块，功能模块与 Chat 只链拥有该设置的页；页 id 只增不改，移走的区重定向到新页。
- **理由。** 工具策略、外部服务器和审批规则是三件事。个性化说明用设置键 `ai.agent.global_instructions`，不读 `~/.agents/AGENTS.md`：那个文件属于编码工具，读它会混入别的工具的说明，还要处理监听和同步。
- **代价。** 设置页变多；移走的区的旧深链落到页顶；全局说明不和其他工具共享。
- **何时重议。** 要做插件、钩子或自动记忆时（PRD §2 的暂缓项），重新评估分组，页 id 仍只增不改。

## 15. 服务商一页改完，密钥按“能调什么”路由

- **约束。** 中转站（sub2api、new-api）把每把密钥放进一个分组，分组决定可调的模型和协议；服务商配置分散在设置与模块两处时，改一个服务商要去两个地方。
- **选择。** 服务商的全部配置在服务商模块，Settings 没有服务商页（D-248、D-250）。多密钥轮换是显式策略：固定主密钥（默认）、顺序轮询、随机，另有失败后冷却。「刷新模型」用每把启用的密钥各读一次列表并记在这把密钥上；候选密钥是列出该模型的密钥加没读过列表的密钥，协议取端点、用户限定与中转站声明的交集（D-258）。
- **理由。** 下一次用哪把密钥只由列表和策略决定，用户能预测；分组差异由系统推导，不用手抄。另建分组实体会在列表变化时分裂，拆成多个服务商要把余额、端点、请求头配多遍。
- **代价。** 冷却只在内存，重启后第一轮会再撞一次坏密钥；轮换不支持权重；同一模型在多个分组时不按价格排优先级；new-api 的分组名不自动读。
- **何时重议。** 中转站提供可读的分组名接口，或用户要按分组设轮换与价格时。

## 16. 模型目录与价格按 models.dev 的三个概念组织

- **约束。** 同一模型在各分发商下 id 写法不同，按 id 字符串定价会取到错误的报价；目录要能离线使用，没有用户选择时不对外发请求。
- **选择。** models.dev 是唯一目录来源，内置快照保证首次离线也有价格，自动同步默认关闭。「模型与价格」一行一个模型，默认只列厂商模型、自建模型和你的服务商在用的模型。生效顺序：服务商 + 模型 > 服务商计价 > 模型级 > 官方价 > 参考价 > 未知；价格设置只在这一页编辑（D-34、D-259）。
- **理由。** 价格按模型生效，请求里的任何写法都解析到同一个模型键；服务商级排在模型级之前，因为它描述这家服务商的账单；价格设置与目录行分开存，同步不会覆盖用户的选择。
- **代价。** 内置快照会变旧，价格不等于账单；没有自家条目的厂商只能用参考价；服务商与分发商不自动对应，只给建议；上游删除的模型留在目录里。
- **何时重议。** models.dev 的数据结构变化，或要做按时间的价格版本、按分发商自动对应时。

## 17. 模型名就是“服务商/模型”，备用模型归调用方，子任务按角色选模型

- **约束。** 别名让同一模型有多个名字，改名会打断授权、备用链和智能体目标；不同调用位置需要不同的备用。
- **选择。** 去掉别名，对外名字是 `服务商名/模型ID`，内部存服务商 id 加模型（D-253）。主智能体与快速、深度思考、看图三个角色各一条备用链，存在 `ai.agent.fallbacks`；网关保留按请求模型匹配的备用规则（D-257）。子任务按角色选模型，存在 `ai.agent.role_models`（D-254）。链最多五个，不递归，不钉密钥，首个内容事件后不切换。
- **理由。** 外部客户端只发一个模型名，网关规则只能按请求模型匹配；智能体的链跟着使用位置走，与会话选哪个模型无关。
- **代价。** 会话不能各配各的链；不支持请求体里的 `models` 数组；不能自定义角色；用量没有角色维度。
- **何时重议。** 用户需要会话级链、自定义角色或按角色统计用量时（PRD §2 的暂缓项）。

## 18. API 工作台：一个事实一个主人，查看跳转不成环

- **约束。** 证书、大响应阈值、历史清理分散在设置与模块里，同一事实有多个编辑入口。
- **选择。** 工作区证书在「环境 › 证书」，大响应阈值在「请求 › 响应与大正文」，清除历史只在历史模块；导入与导出合成一个对话框；Flow 用当前环境；请求网络选项逐项“跟随设置 / 本请求”（D-256）。跳转分查看与派生，派生草稿不计入环检查，导航图守卫卡住查看边的允许列表与无环。
- **理由。** 每个事实一个编辑入口，其他位置只读并链过去，用户不会在两处改出两个值。
- **代价。** 设置页不能直接改证书；移走的区的旧链接改落新区。
- **何时重议。** 新增跨模块的事实，或需要一条会成环的查看边时。

## 19. 用量只在「用量统计」模块里查

- 模块位置部分已被 D-277 取代：调用日志也并入，模块改名「用量与日志」；区间统计只在这里的规则仍有效。
- **约束。** 服务商、网关、Chat 各画一份用量图，口径不同，数字对不上。
- **选择。** 用量的区间统计只在用量模块，别的模块带筛选跳进来；模块有客户端拆分和失败原因视图（D-249）。单次结果留在原处：Chat 每条回复的 token 与费用、上下文环、AI 响应的用量页、网关日志单条记录的 token。
- **理由。** 一处统计，数字只有一个来源，跨模块对得上。
- **代价。** 失败原因只能查 1 小时到 90 天；延迟只有平均值；网关的“今天”是自然日，跳过去是滚动 24 小时。
- **何时重议。** 要做延迟分位数或首字延迟时（PRD §2 的暂缓项）。

## 20. DTO 类型由 Rust 生成，样本冻结退役

- 迁移期保留样本的说法已被 D-265 取代：样本已退出，线格式由生成的类型与契约测试守。
- **约束。** 手写 TS 类型靠冻结样本对照 Rust，新 DTO 只能绕开样本。
- **选择。** 早期 Web 阶段曾用 ts-rs 从 Rust DTO 生成 TypeScript 类型；随桌面端整体迁入纯 Rust GPUI，界面与核心已直接共享 Rust 类型，跨语言生成层已退役（D-260）。
- **理由。** 两侧类型来自同一份定义，改了 Rust 一侧，前端在类型检查时就红。
- **代价。** 测试目标要编译 ts-rs；发布构建与前端包体不变。
- **何时重议。** 手写 DTO 名单清空时，再决定是否去掉名单机制。

## 21. 自研小件换库，选型按现有锁文件对齐

- **约束。** 换库计划和工作区实际的版本与取舍有出入；几处手写解析器的输出由兼容夹具规定，换库会改变输出。
- **选择。** RustCrypto 留在 0.10 线，时间保留 `chrono`；`similar`、`ignore`、`globset`、`jsonschema`、`tokio-util`、`uuid`、`nix`、`if-addrs`、`percent-encoding`、`cookie`、`dom_query`、`serde-saphyr` 取代对应的手写件或旧库（D-261）。文件工具写入用 `cap-std` 从工作区根逐级持有目录句柄，任一级是符号链接就拒写。
- **理由。** RustCrypto 0.11 只有引入 `rmcp` 时才需要，而工作区不依赖 `rmcp`：MCP 客户端是自研的 `agent::mcp`，`rmcp` 仍是 0.x，换过去要连带升级 RustCrypto 并重做现有的大小上限与秘密脱敏；`chrono` 过得了 `cargo deny`。目录句柄让检查之后被换成链接的父目录也改不了落点。
- **代价。** 不采用 `shlex`、`quick-xml`、`serde_json` 的 `preserve_order`、`serde_json_path`、`lopdf`、`pdf-extract`、`serde_yml`，保留的手写解析器继续维护夹具；撤销仍按路径写。
- **何时重议。** 决定引入 `rmcp`（例如要做 MCP OAuth 或 HTTP 推送流）、`cargo deny` 拦下 `chrono`，或兼容夹具放宽到允许换库时。

## 22. 存储只有一份基线 schema，版本不符就拒绝打开

- 版本不符时拒绝打开的说法已被 D-310 取代：主库与 `.secrets` 改名为带时间的 `.bak` 文件后新建空库，见 §70。
- **约束。** 应用还没对外发布，历史增量迁移链长、测试重，每加一列都要写迁移步。
- **选择。** 新库在一个事务里建出完整 schema 并写入当前版本，打开当前版本的库不跑迁移，版本更低或更高的库拒绝打开。没有迁移步，没有升级前备份，新表新列直接写进 `spanbay-store` 的基线 DDL（D-262）。
- **理由。** 未发布阶段没有要升级的用户库；一份基线让 DDL 只有一个来源，审阅改动只看一处。
- **代价。** DDL 变了而版本号不变，旧的开发库照样能打开，读新列时报错，要换新数据目录；旧构建产生的库只能重建。
- **何时重议。** 第一次对外发布之前：发布后的库要能升级，届时恢复前向迁移步与迁移前备份。

## 23. 按职责拆 crate，SQLite 只在 store

- **约束。** 单个核心 crate 编译慢、边界靠约定；任何模块都能直接写 SQL 时，事务和锁的规则审不过来。
- **选择。** 工作区按职责拆成有分支的 DAG：纯类型、纯 LLM 逻辑、仓储、执行器、工作台、LLM、智能体各成 crate，用例层分 `spanbay-app`、`spanbay-app-llm`、`spanbay-app-agent`、`spanbay-app-sync`，`spanbay-core` 做启动与退出编排、门面与跨 crate 集成测试。只有 `spanbay-store` 依赖 `rusqlite`（D-263）。
- **理由。** 依赖方向由 Cargo 强制，改一层就能看出谁受影响；SQL 集中在一个 crate，连接池、事务与语句缓存的规则只审一处。
- **代价。** crate 之间多了重导出和类型搬运；新功能要先判断落在哪一层。
- **何时重议。** 编译时间或改动记录显示某两层总是一起改时，考虑合并。

## 24. 界面文案按区域放在成对的 JSON 里

- **约束。** 文案写在 TS 模块里会混进类型检查和代码审阅，翻译时也很难只看文案。
- **选择。** 每个区域一对 `en.json` 与 `zh-CN.json`，键必须成对，占位符与复数形式一致；以英文为准确定键的类型，切换语言时只重载在用的区域（D-264）。
- **理由。** 文案与代码分开，翻译和审阅只碰 JSON；成对检查让缺键在测试里就失败。
- **代价。** 文案仍计入应用 JS 包体；JSON 没有注释，语境只能靠键名表达。
- **何时重议。** 要支持第三种语言或接外部翻译平台时，重审键的组织和加载方式。

## 25. 新测试只守安全、线格式与业务主路径

- **约束。** 测试量大到拖慢每次改动，不少用例只回显默认值、文案或转发；删掉的测试也带走了它记录的需求。
- **选择。** 新测试只写三类：新的安全不变量；持久化与线格式契约（DDL、DTO、导入导出、网关线格式）；纯业务逻辑的一条主流程加一条错误路径。不给界面渲染、文案、转发、默认值写测试，不逐组件写无障碍测试；删掉的测试不找回（D-265）。
- **理由。** 留下的每条测试都对应一个会被破坏的契约，失败时指向真问题。
- **代价。** 被删用例里隐含的需求要靠 PRD 与代码阅读找回；界面回归更依赖手测与视觉检查。
- **何时重议。** 同类缺陷在没有测试的区域反复出现时，给该区域补契约测试。

## 26. 包体预算只按账本上调

- 已被 D-371 取代：门禁按入口与各导航模块的首开闭包记账，见 §131。
- **约束。** 应用 JS 的余量很小，新增界面会撞线；每次功能提交都顺手上调阈值，预算就没有意义。
- **选择。** 早期 Web 阶段冻结应用 JS 基准并按账本记录上调（D-266）；随 Web/Node 运行时退场，该约束已归档。
- **理由。** 每次上调都有实测数和理由可查，增长速度看得见；硬顶让上调有终点。
- **代价。** 撞线时要先删或拆，功能节奏变慢；不加前端运行时依赖，复杂组件要自己维护。
- **何时重议。** 硬顶用尽而核心场景仍要增长时，按实测重审计量范围。

## 27. 开发构建使用独立数据目录

- **约束。** 开发构建和日常使用共用一个数据目录时，开发中改过的 schema 会让发布版打不开库，调试也会碰到真实数据。
- **选择。** 调试构建写 `com.spanbay.desktop.dev`，发布构建写 `com.spanbay.desktop`；绝对路径的 `SPANBAY_DATA_DIR` 在任何构建里都优先（D-267）。
- **理由。** 发布版数据不受开发构建影响；临时空库只要一个环境变量，冒烟与手测都能隔离。
- **代价。** `npm run tauri:dev` 默认看不到日常数据，要看就显式指向。
- **何时重议。** 要支持多份配置或便携模式时，统一设计数据目录的选择规则。

## 28. 代理按一条规则选路

- **约束。** 请求执行器留空是直连、服务商栈留空是系统代理，同一个设置在两处含义相反；用本机代理软件的用户，管理类请求连不上。
- **选择。** 请求、服务商、扫描与网页搜索按同一条规则出站：对象自己的代理 → 本地地址与 `no_proxy` 直连 → 全局代理 → 留空走系统代理，`direct` 显式表示不用代理。设置界面三选一，带连通测试。经系统代理时不钉扎地址，只按字面量判定，与显式代理一致（D-268）。
- **理由。** 用户只学一条规则；系统代理覆盖最常见的本机代理配置。
- **代价。** 跟随设置、全局留空的请求改走系统代理；经代理时 DNS 结果由代理决定，SSRF 守卫只能判定字面量。请求自己的代理留空仍是直连。脚本附加请求、OAuth 与网页抓取只认显式代理，MCP HTTP 跟随系统代理。
- **何时重议。** 要支持 PAC 脚本或按主机分流时，扩展规则本身，不在单个调用方加特例。

## 29. 流程判定计入请求自带断言，条件读作“仅当…时运行”

- **约束。** 步骤只看自己的断言时，请求自带断言失败的步骤仍显示通过；条件字段的写法让用户猜错跳过方向。
- **选择。** 步骤判定把请求自带断言与步骤断言一起求值，步骤可以单独关掉请求自带断言；条件统一写作“仅当…时运行”。画布换成竖向步骤列表，运行内 Cookie 会话默认开；AI 步骤只用 HTTP 断言（D-269）。
- **理由。** 同一个请求单独发送和在流程里发送得到同一个判定；列表比画布更容易读出执行顺序。
- **代价。** 依赖旧判定的流程会由绿变红，要调整断言或关掉请求自带断言；卡片网格、箭头和缩放没有了。
- **何时重议。** 需要分支、并行或按数据行循环时，重设流程模型。

## 30. 网关额外主机强制令牌，受限令牌约束备用目标

- **约束。** 额外允许主机会把网关开放给隧道或局域网；受限客户端在主模型失败时，经备用规则仍可能调到允许范围外的模型。
- **选择。** 配了额外主机就必须开令牌，设置校验拒绝“关令牌 + 额外主机”，旧配置在启动时读作令牌开并给出说明。客户端的允许范围同时约束备用目标，范围外的备用在规划时跳过并记原因（D-270）。
- **理由。** 允许范围是授权，授权不能经故障转移绕开；入口扩大时身份校验必须跟上。
- **代价。** 受限客户端在主模型失败时直接收到错误；已有额外主机配置的用户要重新发令牌。
- **何时重议。** 要做按客户端的备用链或公网部署时，重审授权模型。

## 31. Mock 按 Mockoon 语义选响应

- **约束。** 没有规则的响应抢先生效，用户按规则顺序配置的路由会返回意料之外的响应；Demo 与真实 Mock 的结果也会分叉。
- **选择。** 无规则的响应永不算命中；按规则顺序都不中时返回默认响应，没有默认返回第一个；回落模式都不中就让位；停用规则时总返回默认响应。Demo 用同一规则，两侧由共享夹具对拍（D-271）。
- **理由。** 与 Mockoon 一致，用户的经验和导入的配置可以直接沿用；默认响应在界面上标出，结果可预测。
- **代价。** 已存路由的行为会变：抢先生效的无规则响应不再命中，要把它设为默认。
- **何时重议。** Mockoon 改变选择语义，或要支持它没有的模式时。

## 32. 集合导出默认剥离字面量凭据

- **约束。** 导出文件常被分享或提交进仓库，认证字段和凭据请求头里的字面量会随之泄露。
- **选择。** 导出默认把凭据位置的字面量写成空串：认证字段、凭据名请求头、凭据名查询参数与表单字段、URL 用户信息（连同 `@` 去掉）。位置取自复制为代码与文件夹同步共用的凭据位置函数；变量引用照常保留，并提示剥离了几处；勾选“包含字面量凭据”才写出原值（D-272）。
- **理由。** 默认安全；变量引用让导入方用自己的环境补值。
- **代价。** 依赖导出带凭据的流程要多勾一次；不含 `{{` 的值一律按字面量处理。
- **何时重议。** 要支持带口令保护的导出包或团队共享密钥时。

## 33. 智能体默认值偏向少打扰、可恢复

- **约束。** 长任务里逐次询问只读操作会打断用户；工具输出被截断后模型拿不回全文；受保护环境的响应原文进模型会泄露生产数据。
- **选择。** 新对话的默认权限只给“每次询问”与“自动批准只读”两档，已存的完全权限读作自动批准只读；提示缓存在已知支持的目标上默认开；超限的工具输出脱敏后落盘，模型凭句柄分段读取，随对话删除；受保护环境的响应只给形状与短错误文本（D-273）。
- **理由。** 只读操作风险低，逐次询问换不来安全；落盘让截断可恢复；缓存只在已知支持时开，账单变化可预期。
- **代价。** 本机明文留存工具输出，脱敏覆盖不了任意短秘密；缓存首次写入更贵；生产排障时模型看不到正常响应的值。
- **何时重议。** 落盘总量或缓存命中率的实测与预期不符，或用户要按环境放开原文时。

## 34. 权限评估顺序固定，规则 Block 先于强制询问

- **约束。** 用户写的 Block 规则排在强制询问之后，询问卡就给了用户批准自己明确禁止的调用的机会；每个决定也要能在审计里查到出处。
- **选择。** 顺序固定为硬阻止 → 规则 Block → 强制询问 → 作用域 Allow → 单工具 Allow → 模式默认，审计写明每个决定来自哪一层。Full access 越不过前三层，不关闭 OS 沙箱，只持续到重启；未受信任的 MCP 服务器在 Full access 下仍要询问（D-274）。
- **理由。** 用户的明确禁止不该被一次点击推翻；层级写进审计，事后能解释每次放行和拒绝。
- **代价。** 依赖“询问后放行被 Block 的调用”的用法改为直接拒绝；长任务遇到重启要重新开 Full access。
- **何时重议。** 引入组织级或远程下发的策略时，重设层级。

## 35. 系统通知从 Rust 侧发出

- **约束。** 智能体等审批或跑完时用户常在别的窗口；Webview 被隐藏或节流时，前端发通知不可靠，还可能把命令内容带进通知。
- **选择。** 核心订阅关注事件，窗口不在前台时由 Rust 发系统通知，前端只管设置（关闭、需要你时、需要你和运行结束）。通知只写对话名、工具类别与风险或运行结果，不写命令、路径和参数；同一对话有冷却；点击通知把窗口带到前台并打开该对话（D-275）。
- **理由。** 通知不依赖 Webview 是否在跑；内容在 Rust 一处控制，敏感参数进不了系统通知中心。
- **代价。** 各平台的通知权限与点击回调能力不同，macOS 第一次真发通知时才询问权限；没有发送测试通知的入口。
- **何时重议。** 要做通知历史、按项目静音或移动端推送时。

## 36. 探测结果不直接改路由

- **约束。** 一个密钥组测出某能力失败，若直接写进路由用的能力矩阵，这个模型会对所有密钥悄悄跳过。
- **选择。** 探测只按密钥记录结果；路由读的能力只由用户 Apply 写入，Apply 按模型与能力合并本次各密钥的结果，任一密钥通过即记支持；撤销只作用于本服务商（D-276）。
- **理由。** 失败可能只属于某个分组、某次限流或某个样本；让用户决定，一次错判不会永久排除可用目标。
- **代价。** 确实不支持的能力在 Apply 之前仍会被路由过去，并收到上游错误。
- **何时重议。** 有足够样本与过期规则支撑自动判定时，按 §3 的重议条件另行设计。

## 37. 九个导航目的地，调用日志并入用量，网关归服务商

- **约束。** 用量、调用日志和网关设置分散在三个模块和设置页里；改成按任务分组的导航会打乱已有的快捷键和习惯。
- **选择。** 侧栏保留九个目的地，API 与 AI 两组按作用域分，⌘1–⌘8 不变。调用日志与详情抽屉从服务商搬进用量，模块改名「用量与日志」；设置里的网关访问、客户端与网关备用规则搬到服务商 › 网关；Mock 默认值、用量保留与余额刷新留在设置（D-277）。
- **理由。** 日志和用量回答同一个问题：调用花了多少、在哪里失败；网关的访问与客户端是服务商侧的运行配置，放在一起改一次就够。
- **代价。** 旧的设置网关深链改写到新位置；服务商模块不再有活动标签。
- **何时重议。** 导航目的地要增减，或网关要独立成模块时。

## 38. 改造中不做的项

- **约束。** 范围要能交付；几项设计稿画过的功能依赖尚不稳定的评测需求，或要额外的持久化形状。
- **选择。** 不做声明式 AI 断言，不做步骤停用、总会执行与分组，不做智能体运行详情抽屉和发送测试通知的入口，不做流程按数据行循环与多次试跑汇总；界面上不留这些功能的按钮（D-278）。
- **理由。** AI 步骤先用 HTTP 断言就能判定；运行进展已在右栏与历史里；通知效果取决于系统权限，真触发一次更直接。
- **代价。** 评估 AI 输出只能靠 HTTP 断言与脚本；长流程不能临时停用某一步；排查通知要真触发一次审批。
- **何时重议。** 有稳定的评测需求和样本时做声明式断言；流程长到需要分组时做步骤控制；右栏装不下诊断信息时做运行详情；通知权限成为常见问题时做测试通知。

## 39. 未绑定是对话的主路径，工具按绑定裁剪

- **约束。** 没有工作区的用户也要能发出第一条消息；调用必然失败的工具不该出现在模型面前。
- **选择。** 对话可以不绑定工作区并照常发送。未绑定（或绑定的工作区已删除）时，六个依赖工作区的工具不进工具表，系统提示写 `Workspace: none`，其余工具、探测与调用日志照常（D-279）。起始页复用头部的工作区与项目文件夹芯片，选择存在 `newChat.binding`，可选“不绑定”，不改壳层的活动工作区；没有工作区时给“创建工作区”，沿用壳层的措辞并跳到 API 模块。补绑只经头部或失败行的按钮显式完成，下一条消息起生效；不自动创建默认工作区，不静默补绑。
- **理由。** 在回合开始前处理缺失的前提，比让模型调用失败再解释省轮次；裁剪走“关闭某工具”的同一条生产路径。
- **代价。** 补绑后工具表变化，下一条消息的提示缓存未命中一次，作为已接受的成本；六个工具名只在 Rust 登记，前端读 `needs_workspace`。
- **何时重议。** 作用域工具增减，或需要“默认工作区”时。

## 40. 工具失败以结果文本首行的 code 为单一来源

- **约束。** 失败行要说人话并给下一步，但后端错误是英文原句；新增 DTO 或存储字段要动数据库和跨语言契约。
- **选择。** 结果文本首行写 `{"error":{"code":"…"}}`，英文原文跟在后面（D-280）。码只有六个：`not_bound`、`workspace_deleted`、`tool_unavailable`、`invalid_arguments`、`timeout`、`outside_folder`；`not_found` 与 `sandbox_denied` 没有单一出口，不设码。`submit_plan` 的结果同约定。前端只对内置工具读首行；折叠态不显示后端原文，只写类别、退出码或“展开查看原因”。`shell` 的退出码由 Rust 写进审计行。
- **理由。** 模型读到的和界面画的同源；前端用穷尽 `Record` 映射，后端加码，前端编译失败。
- **代价。** 模型也读得到首行，所以首行极短；检查阶段的越界是硬阻止，没有 code，显示成阻止行。
- **何时重议。** 出现结构化的沙箱拒绝出口时，再加 `sandbox_denied`（只加不改线格式）。

## 41. 需要你只有一个位置，运行看板并入对话列表

- **约束。** 审批、提问、计划批准和费用暂停要有一个固定的处理位置；内联批准会让用户在看不到命令全文时点允许。
- **选择。** 关卡区是唯一可操作位置，线程里只有不可操作的标记行，列表行、侧栏计数与头部角标只是入口（D-281）。“需要你”的计数与分组不受范围限制，点行只打开对话并聚焦关卡卡；“停止全部运行…”确认框点名对象，不做行内批准与批量允许。运行看板的布局与入口后续演进见 §136。
- **理由。** 一个位置、一个计数；批准前必须看到完整对象。
- **代价。** 列表里不能直接批准，多个运行要逐个进入对话处理。
- **何时重议。** 桌面反馈强烈要求批量分诊时，在需要你的行上补审批摘要，仍不加内联批准。

## 42. 输入区：一枚模式芯片、单行 StatusLine、整行暂停条

- **约束。** 底栏只容得下少数常驻控件；权限与计划是两个状态，但要在一处看清；停止后队列暂停必须说出来，引导不能悄悄作废待批准的命令。
- **选择。** 底栏常驻五项。模式芯片同时呈现权限与计划，状态仍是三档权限加独立的计划开关；`cycleMode` 默认 `Mod+Shift+O`，在自动批准只读、每次询问、计划之间轮换，跳过必经对话框的完全权限（D-282）。`Shift+Tab` 是输入框里的反向焦点，覆盖会形成键盘陷阱；`Mod+Shift+.` 在美式键盘上产生 `>`，匹配不上。审批在等时 `Mod+Enter` 无动作，另给“引导并取消这次批准”。停止后暂停条整行写原因，暂停时再发的新消息直接发出。取消的状态词写“已取消”，后半句列出已产生的效果，落实 `design.md` §9.4；动作词写“停止”。
- **理由。** 同一个键在一个状态里只有一个含义；说出暂停与后果比静默承诺更诚实。
- **代价。** 重启后不声称暂停（`queue_paused` 不持久化），只显示“待发 N”。
- **何时重议。** 需要跨重启保持暂停时，连同存储形状一起设计。

## 43. 线程：过程块切段，计划与提问各有块，改动审阅集中

- **约束。** 过程信息多而结论要外露；失败不能撑开线程；改动行数与撤销只该在一处。
- **选择。** 计划与提问是线程里的独立块，把过程块按时间切成若干段，计划批准后的执行步骤落在计划之后（D-283）。出错回合不自动展开，过程块头写“N项失败”。DiffCard 只读，改动审阅集中在面板“改动”页与回合末的改动条（审阅改动、全部保留）。不做回退或检查点，保留逐文件撤销与“分支为新对话”。`⌃O` 展开或收起本对话的全部步骤，不持久化；没有单独的聚焦视图。
- **理由。** 过程折叠、结论外露；撤销只在面板一处发生。
- **代价。** 重开对话后编辑行的“+n −m”依赖 `aux.changes` 回填；状态行给了“重试”时，脚部不重复给。
- **何时重议。** 要做整轮检查点或按行审阅时。

## 44. 客户端证书支持加密 PKCS#8 与 PKCS#12

- **约束。** TLS 口令存在秘密库里却没人读取，加密私钥一律失败，也不支持 `.p12` 与 `.pfx`；rustls 后端不能解密 PKCS#8，也读不了 PKCS#12。
- **选择。** 引入 `pkcs8` 0.10（`encryption`），建客户端时用秘密库里的口令解密 `ENCRYPTED PRIVATE KEY`；引入 `p12-keystore` 0.2.1，把 PKCS#12 转成 PEM 交给 reqwest。旧式 OpenSSL `Proc-Type` 加密不支持，报错并提示用 `openssl pkcs8 -topk8` 转换（D-284）。
- **理由。** 两者都在 RustCrypto 0.10 线上，与 §21 一致；依赖全是正式版，`x509-parser` 与 `rand` 已在锁文件里。比换成 native-tls 后端改动小得多。
- **代价。** 多十余个密码学 crate。客户端缓存键只看是否存有口令，口令变更不触发失效，旧口令能用时继续用旧客户端。
- **何时重议。** rustls 生态有了官方的 PKCS#12 或加密 PKCS#8 支持，或需要支持旧式 PEM 加密时。

## 45. 主请求、取令牌与脚本附加请求共用 TLS 材料

- **约束。** mTLS 或私有 CA 环境下主请求能通，OAuth 取令牌和 `pm.sendRequest` 却失败。
- **选择。** `AuxiliaryNetwork` 携带 `TlsMaterial`，即工作区证书加口令读取器。三类客户端都信任网络设置的 CA 文件与工作区 CA，并出示按主机匹配的同一张客户端证书；脚本客户端按所出示的证书分别缓存（D-285）。
- **理由。** 根证书与身份只在一处读取，三个客户端不会彼此不一致。
- **代价。** 取令牌要在阻塞池里读证书文件，多一次线程切换；令牌卡片也要读工作区证书。
- **何时重议。** 出现按请求自定义 CA，或按调用方区分证书的需求时。

## 46. 脚本写入的变量按名称与形状判定机密

- **约束。** `pm.*.set` 新建的键一律是普通变量，登录脚本抓到的令牌会明文进入导出、Postman 导出和同步目录；写入已停用的变量还会把它重新启用。
- **选择。** 新键名是凭据名或值带令牌形状时建成机密。凭据名与脱敏共用 `REDACT_QUERY_KEYS` 和 `is_secret_header_name`，另加 jwt、session、sid、bearer、auth 一类；令牌形状由 `is_token_shaped` 判断。已有机密保持机密；普通变量在两种情况下写入凭据会升为机密：它从未有过值（导入的 `token: ""`），或新值带令牌形状而旧值没有（`<your token>` 一类占位）。已经存着令牌的普通变量保持用户的选择。写入已停用的变量只更新值，保持停用并在控制台提示（D-286）。
- **理由。** 凭据泄露进 Git 和分享文件后无法收回；按名称与形状判断能覆盖常见登录脚本，也不改 schema。
- **代价。** 启发式会误判，名为 auth 的普通变量会存成机密，没有特征的随机令牌会漏判；脚本对已停用变量 set 之后 get 读不到值。
- **何时重议。** 引入“本机当前值”这一层，或误判反馈明显时。

## 47. 脚本的 Cookie 只读写请求主机相关的条目

- **约束。** 前置脚本里 `pm.cookies` 恒为空，也没有 `jar()`，读 `XSRF-TOKEN` 写回请求头的常见写法做不到；导入的脚本若能任意读罐，就能把无关站点的会话 Cookie 经 `pm.sendRequest` 送出去。
- **选择。** 前置阶段 `pm.cookies` 读请求 URL 会带上的罐内 Cookie，后置阶段再叠加响应 Cookie。`jar()` 只允许请求主机本身、父域与子域；这个主机在本阶段第一段脚本运行前定下（前置阶段按当时的变量解析请求 URL，后置阶段取实际发出的 URL），脚本改写 `baseUrl` 一类变量挪不动它。写入立即用于本次主请求；只有记录型发送且请求使用 Cookie 罐时才存库，与响应 Cookie 相同（D-287）。
- **理由。** 覆盖 Postman 的常见用法，又不给导入脚本开出跨站读取的通道；持久化条件与响应 Cookie 一致，用户只需记一套规则。
- **代价。** 比 Postman 的域名白名单更严，跨域读写要改在目标请求的脚本里做；AI 运行与 Flow 中的写入不落库。
- **何时重议。** 用户需要跨域读取 Cookie 时，可以改成在环境里声明允许的域名。

## 48. OAuth 2.0 发送期令牌自动刷新、单飞与 401 重试

- **约束。** PKCE 令牌过期即报错，集合运行会中途失败；401 不让缓存失效；没有 audience、resource 一类额外参数；并发发送各自取令牌。
- **选择。** 卡片令牌过期且有刷新令牌时自动刷新并存回，同一配置用异步互斥单飞。401 后只在有换令牌的路时重发一次：客户端凭据与密码授权能重取，PKCE 要有刷新令牌。拿到另一枚才让被拒的存储令牌失效；没有路或换不到就返回原 401，令牌原样保留。发送附上的每一枚令牌都经 `StoredOAuthTokens::sent` 报告，供智能体按值掩码。`extra_params` 随令牌请求与授权 URL 发送，保留字段名不发送；它计入 `token_key`，没有额外参数时键不变（D-288）。
- **理由。** 与 Postman 的自动刷新一致；单飞避免集合运行瞬间打爆令牌端点，只重发一次避免循环。
- **代价。** 非幂等请求在 401 后会再发一次，好在服务器已经拒绝，副作用通常没有发生；改额外参数会让已存令牌换键，要重新取。
- **何时重议。** 需要区分授权请求参数与令牌请求参数，或像 Postman 的 `send_as` 那样放进请求头或 URL 时。

## 49. 响应解码支持 br、zstd 与 deflate

- **约束。** reqwest 只开了 gzip，请求显式要 br 或 zstd 时（Firefox 复制的 cURL、导入的集合），格式化、JSONPath 与断言拿到的是压缩字节。
- **选择。** 工作区的 reqwest 打开 `brotli`、`deflate`、`zstd` 特性。`Cargo.lock` 新增 `zstd`、`zstd-safe`、`zstd-sys`，`zstd-sys` 编译内置的 C 版 libzstd；它的许可是 BSD，`about.toml` 因此接受 BSD-2-Clause（D-289）。
- **理由。** 与浏览器和 cURL 能解的编码一致，改动只在特性开关；纯 Rust 的 zstd 实现还没有更成熟的。
- **代价。** 多一个 C 依赖与构建步骤，发布二进制变大。2026-11-19 的实测条件是 macOS arm64、rustc 1.99.1 与工作区默认 release 配置。探针二进制用同一份 `Cargo.lock` 构建，只依赖 reqwest（其余特性与工作区相同），打开这三个特性后大 325,664 字节（约 318 KiB），strip 后大 301,584 字节（约 295 KiB）。完整的 `spanbay` 二进制没有单独对比，链接的是同一组解码器，增量应在同一量级。特性对整个工作区生效，网关等其他出站客户端也会声明这些编码。
- **何时重议。** 二进制体积成为发布约束、网关直通需要保留原始编码，或出现成熟的纯 Rust zstd 实现时。

## 50. HTTP 超时拆成空闲超时与可选总时限

- **约束。** SSE、NDJSON 与长轮询会被唯一的 30 秒总超时切断，超时后状态码、响应头和已收数据全部丢失。
- **选择。** `timeout_ms` 表示空闲超时，管建连、等响应头以及正文两块之间的间隔，用 reqwest 的 `connect_timeout` 与 `read_timeout` 实现。每个请求另有可选的 `total_timeout_ms` 总时限，覆盖所有重定向和正文；单次发送与智能体发送默认不限，集合运行与 Flow 步骤没设时按 5 分钟算，无人值守的运行不会被心跳流挂住。它存在请求的 `network_options` JSON 里，不进全局设置，因为设置注册表冻结（D-290）。
- **理由。** 持续有数据的流不该被切断，curl 与 Postman 也都区分空闲与总时限。
- **代价。** 单次发送没设总时限时，一直发心跳的流要读到正文上限或用户停止才结束，智能体发送另有硬上限；集合运行与 Flow 里超过 5 分钟的下载要在请求上设更长的总时限。Flow 步骤的“每次尝试超时”落在空闲超时上。
- **何时重议。** 需要全局可调的默认总时限，或 5 分钟的运行默认值误伤正常请求时。

## 51. 超时与停止时保留部分响应的范围

- **约束。** 执行管线对取消约定“无历史、不提交后置变量”，集合运行、Flow 与智能体都依赖它。
- **选择。** 收到响应头之后的空闲超时与总时限，对所有调用方都返回部分结果，即成功并标 `body_incomplete`。“停止”只在界面的单次发送里保留部分结果（`ExecutionMeta::interactive`），这时跳过后置脚本并照常写历史；其余调用方的停止仍按取消处理（D-291）。
- **理由。** 单次发送是看流的唯一入口，批量运行需要可预期的取消语义。
- **代价。** 集合运行与 Flow 里超时得到的部分响应会进入断言，多半失败，也不会作为网络失败触发步骤重试。
- **何时重议。** Flow 的 `retry_on` 需要单独区分“正文超时”时。

## 52. 流式响应读完后整体返回

- **约束。** 逐事件推送要新的 IPC 流形状和前端流式查看器，还要和大正文外置配合。
- **选择。** 交付空闲与总时限的拆分、部分结果保留，以及正确的截断与大小报告；读体结束后整体返回结果，不逐条推送事件（D-292）。
- **理由。** 先用最小的正确改动解决“流被切断、数据全丢”。
- **代价。** 看 SSE 只能等停止或超时之后一次看到全部事件。
- **何时重议。** 做专门的 SSE 查看器时，复用 llm-protocol 的有界 SSE 解析器与带序号的 Channel。

## 53. 发送并保存到文件只认原生保存框给的路径

- **约束。** Webview 传来的路径不是授权，正文上限又会截断大下载。
- **选择。** 命令 `request_draft_download_run` 由壳层先打开原生保存框，再发送请求，把整段正文边收边写进文件，不设上限；捕获进内存的部分仍受上限约束。保存框取消就不发送，演示版不支持（D-293）。
- **理由。** 路径只来自原生对话框，下载大小不受内存上限限制。
- **代价。** 受保护环境要确认时，确认后的重发会再弹一次保存框；文件在收到响应头后才创建，HEAD 或空正文得到空文件。
- **何时重议。** 确认流程能复用已选路径时。

## 54. 断言新增通用比较与 JSON Schema 校验

- **约束。** 断言只有相等与存在两类判断，已存数据又必须原样加载。
- **选择。** 新增 `Check`（目标、运算符、期望值）与 `JsonSchemaValid`（可带 path），旧变体保留不迁移。HTTP 的 schema 校验接受 OpenAPI 注解关键字与 `x-` 扩展，不执行 `nullable` 语义。脚本提供 `pm.response.to.have.jsonSchema` 与 `tv4.validate` 子集，与断言共用同一个离线校验器（D-294）。
- **理由。** 兼容旧数据，同时覆盖取反、比较、正则、类型与契约校验。
- **代价。** 新旧两套写法并存，同一检查能写成两种形式；Postman 导出要翻译新种类。
- **何时重议。** 决定把固定种类的断言迁移成 `Check` 时。

## 55. Cookie 过期时间当场换算为绝对时间

- **约束。** schema 不能改，`cookie_jar` 表只有文本列 `expires` 与 `max_age`；Max-Age 按 `updated_at` 起算时，编辑会给 Cookie 续命，甚至让已过期的复活。
- **选择。** 收到响应 Cookie 或手动改过期时间时，按 RFC 6265 §5.3 当场算出绝对过期时间：Max-Age 优先，不大于 0 记为 epoch，否则用 Expires。结果以 IMF-fixdate 写进 `expires`，`max_age` 留空。Expires 解析接受连字符写法与两位年份，忽略对不上的星期，解析不了就当会话 Cookie。仍带 `max_age` 的导入行从不变的 `created_at` 起算（D-295）。
- **理由。** 不改表就得到不随编辑漂移的绝对过期时间，解析继续用 `httpdate`，不加依赖。
- **代价。** 界面上看不到原始的 Max-Age，只看到换算后的日期；精度到秒，最晚封顶到 9999 年。
- **何时重议。** 下一次重建基线 schema 时，加一列毫秒整数的过期时间并改用整数比较。

## 56. 本地开发 Cookie 的作用域与安全上下文

- **约束。** 按浏览器与 RFC 6265，公共后缀域名只有等于请求主机时才能存，而且只能存为仅限主机；回环地址算安全上下文。
- **选择。** Domain 是公共后缀（`localhost`、单标签主机）且等于请求主机时，存为仅限主机。不经代理直连的回环主机（`localhost`、`127.0.0.0/8`、`::1`）上的 Secure Cookie 允许经 http 发送（D-296）；走代理或 `*.localhost`（解析器不把它钉在回环上）时不发。
- **理由。** 本地开发服务器常发 `Domain=localhost` 或 Secure Cookie，整条丢弃或永不回发都与浏览器行为不符。
- **代价。** 回环上的 Secure 标志挡不住明文传输，但回环流量不出本机，风险可以接受。
- **何时重议。** 要支持用别的主机名做本地开发时，例如 `/etc/hosts` 指向本机的名字。

## 57. 值为空的机密也算变量定义

- **约束。** 同步、导入或清空之后，机密可能只有名字没有值；发送、未解析扫描与对比对它的处理各不相同。
- **选择。** 最窄一层里启用的那一行就是这个名字的定义。值为空的机密也算定义，它遮住下层的同名值，本身不解析，发送时报未解析。规则只在 model 层的 `EnvironmentVariable::needs_value` 里实现一次（D-297）。
- **理由。** 避免把下层同名令牌（例如 dev 环境的）发到生产主机，显示与实际发送保持一致。
- **代价。** 依赖“空机密回落到 Globals”的用法会报未解析，要用户填值或停用这一行。
- **何时重议。** 产品决定给空机密提供显式的“继承下层”开关时。

## 58. 手动添加 Cookie 复用 cookies.txt 导入

- **约束。** 新增 IPC 命令要同时改 DTO、适配器与 Demo 覆盖表等一串文件。
- **选择。** 不加命令。导入命令按内容识别格式：以 `{` 开头按 Cookie 罐 JSON 读，否则按 Netscape cookies.txt 读。“添加 Cookie”对话框在前端把主机、路径和 `name=value` 或整条 Cookie 头组成 cookies.txt 行，再走同一个导入（D-298）。
- **理由。** 所有 Cookie 写入只有一套校验与替换规则，顺带支持浏览器、curl、wget 导出的文件。
- **代价。** 手动添加的只能是会话 Cookie，值里不能有制表符或换行，要设过期时间得添加后再编辑；Demo 里要有一份 TS 版的 cookies.txt 解析。
- **何时重议。** 需要在添加时直接设 SameSite 或过期时间时。

## 59. 定义变量只升级机密，不降级

- **约束。** “定义变量”与 OAuth 的“使用”会覆盖同名变量，把已有机密改成普通变量后，凭据会进入导出与同步。
- **选择。** 核心写入时只升不降（`is_secret |= 请求值`）。改成普通变量只能在环境编辑器里显式切换类型；从认证字段打开的定义对话框默认勾选机密（D-299）。
- **理由。** 比降级前再确认一次简单，也没有误操作的可能。
- **代价。** 想把机密改为普通变量，必须去环境编辑器操作。
- **何时重议。** 出现在定义对话框里直接降级的明确需求时。

## 60. 重新导入同名集合时按配对原地写回

- **约束。** 库结构不能改，没有地方记录上次导入的基线；“替换”每次生成 `__import_N` 新 ID，Flow 步骤与历史关联随之断开。
- **选择。** 新增“更新”冲突选项，作为集合撞名时的默认值；“替换”同样保留 ID。文件夹按名称路径配对；请求先按方法加 URL 路径配对，同目录优先，再找全集合，最后按同目录的名称配对。配对上的行用 upsert 原地写回，ID、历史外键和 Flow 引用不变（D-300）。
- **理由。** 重新导入的核心诉求是不毁掉用户的补充与引用，ID 不变是不用改 Flow 和历史的唯一办法。
- **代价。** 改了路径又改了名的请求会被当成新请求。
- **何时重议。** 允许增加存储结构（例如给集合加导入来源与快照）时，改成三方合并，并在预览里给出逐字段差异。

## 61. 重新导入的“更新”与“替换”

- **约束。** 用户在 SpanBay 里补过的断言、脚本、凭据和请求不能被文件冲掉，但用户有时就是要以文件为准；没有导入基线，只能两方合并。
- **选择。** “更新”只覆盖文件拥有的字段：参数与请求头按键合并，文件里的空值保留已填值；文件没自带的断言、脚本、网络选项和示例保留，认证同类时保留，AI 模式与文件里没有的请求也保留。“替换”以文件为准，移除未配对的请求，并删除其他同名集合。两者都用一个撤销令牌回滚：删除新增项，用原 ID 写回旧树（D-301）。
- **理由。** 默认选项保住用户的补充，需要以文件为准时有明确的出口。
- **代价。** “更新”从不删除，文件里删掉的参数或请求头不会从已存请求里移除，要用户手动处理或改用“替换”。
- **何时重议。** 有了导入基线、可以三方合并时。

## 62. 请求示例存进网络选项 JSON

- **约束。** 不能改 schema。
- **选择。** `Request` 新增 `examples`，最多 20 个，单个正文 64 KiB。存储层把它放进已有 `requests.network_options_json` 对象的 `examples` 键，读时拆出；保存输入不带 `examples` 时沿用已存示例，带列表（含空列表）时整体替换，编辑器的「说明」页借此删除示例；历史快照去掉示例（D-302）。
- **理由。** 零 DDL 改动，旧读者忽略未知键，同步文件经 serde 自然带上。
- **代价。** 示例与网络选项共用一列，直接查 SQL 时语义不直观；示例增大了 `list_requests` 的读取量。只能查看和删除示例，还没有“存为示例”与“从示例生成 Mock”的界面。
- **何时重议。** 下一次允许改基线 schema 时，把示例移到独立的列或表，并补上这两个界面。

## 63. Postman 导出把断言写成带标记的测试

- **约束。** Postman v2.1 没有声明式断言字段。
- **选择。** 每条断言写成一行 `pm.test`，行尾带 `// spanbay:assertion <JSON>` 标记，整组用 begin 与 end 注释包住。能翻译的断言在 Postman 与 newman 里真实执行：状态、请求头、经 lodash `_.get` 的简单 JSONPath、正文包含、耗时与大小。不能翻译的写成 `pm.test.skip`。重新导入时按标记还原成断言，并从测试脚本里去掉这段（D-303）。
- **理由。** 断言既能在 CI 里跑，又能无损回到 SpanBay。
- **代价。** 导出的测试脚本里多出生成的代码；复杂 JSONPath 在 Postman 里只是跳过的测试。
- **何时重议。** Postman 推出原生断言字段，或 SpanBay 有了自己的无头运行器时。

## 64. Postman 导出的网络选项与环境

- **约束。** Postman 没有单请求的超时、重试或代理字段；导出又不该依赖当前激活的环境。
- **选择。** 网络选项只把请求自有、且偏离 Postman 默认值的字段写进 `protocolProfileBehavior`，超时、重试、代理和 HTTP/1.0 每类各给一条警告。选了环境时，环境变量覆盖同名集合变量，再追加环境独有的变量；集合导出默认不带环境（D-304）。
- **理由。** 能表达的照实写，表达不了的明说。
- **代价。** 导出到 Postman 后，这些传输设置要手动补。
- **何时重议。** Postman 增加对应字段时。

## 65. cURL 与网络选项双向映射

- **约束。** 浏览器的“复制为 cURL”从不写 `-L`；`timeout_ms` 是空闲超时，`total_timeout_ms` 才是总时限（D-290）。
- **选择。** 导入时 `-L`、`--location-trusted`、`--max-redirs`、`-k`、`-m`、`--retry`、`-x` 与 HTTP 版本参数写成请求自有值并移出继承，`-m` 对应总时限。没有 `-L` 时保持默认的跟随重定向，`--compressed` 无需转换，证书类参数提示去「设置 › 证书」。代码片段只输出请求自有的字段；粘贴 cURL 合并到草稿时，只覆盖命令里写了的网络选项（D-305）。
- **理由。** 粘贴浏览器复制的命令仍按浏览器的行为跟随重定向；导出的命令能直接运行并复现 SpanBay 的传输行为。
- **代价。** `follow_redirects` 为假的请求导出再导入会变回跟随，因为 cURL 没有表示“不跟随”的参数；所有 cURL 片段都多了 `-L`。
- **何时重议。** 用户要求严格的 cURL 语义（没有 `-L` 就不跟随）时，改成显式选项。

## 66. 跨工作区复制带上机密

- **约束。** 两个工作区在同一台机器、同一个库里。
- **选择。** 复制请求、目录子树或整个集合时用新 ID，在一个事务里写入。集合的机密变量与请求的代理密码随副本复制到新 ID 名下；Flow、历史、Cookie 不复制。与源同位置的副本加“(copy)”，同名目录或集合用“(copy N)”避重（D-306）。
- **理由。** 复制发生在同一个本机保险库内部，不越出信任边界；把集合搬到另一个工作区时，用户期望凭据直接能用。
- **代价。** 机密值在保险库里多存一份，删除源时不清理副本。
- **何时重议。** 引入多用户或系统凭据保护，或用户要求复制时剥离秘密时。

## 67. 自定义 HTTP 方法与表单段类型暂缓

- **约束。** `HttpMethod` 是 Copy 枚举，被执行器、存储、Mock、智能体工具与前端方法选择器穷尽匹配；`FormPart` 的字面量散在多个包的测试里。
- **选择。** 只做 Postman 原始正文语言映射，表单段 `contentType` 丢失时给出提示；不新增 `HttpMethod::Custom` 与 `FormPart.content_type`（D-307）。
- **理由。** 两项都要跨执行器、存储、Mock 与编辑器同步改动，冲突面大而优先级低。
- **代价。** Postman 的自定义方法仍改成 GET 并警告，按段指定的 Content-Type 仍会丢失并警告。
- **何时重议。** 一次性实现时，`Custom` 一律按非安全方法处理，执行器签名与非签名两条 multipart 路径都要遵循段级 Content-Type。

## 68. 历史保留按来源分桶

- **约束。** 不改 schema；除 Mock 外的来源共用 2000 条，一次集合运行就能冲掉手工 Send 的记录。
- **选择。** request、agent、runner、flow 四类各有一份 `data.history_retention` 预算，Mock 仍是 500。runner 与 flow 用窗口函数累计行数，按整次运行淘汰；最新一次运行总是完整保留，没有 `run_id` 的行自成一组（D-308）。
- **理由。** 每类来源只挤掉同类记录，按整次运行淘汰也不会留下半个运行组。
- **代价。** 每个工作区最坏保留 4 倍条数再加 500，库体积跟着变大；修剪多一次 GROUP BY，插入后先用索引 COUNT 短路。没有置顶。
- **何时重议。** 出现库体积投诉，或要做置顶、按来源单独设条数时，这些都需要新列或新设置键。

## 69. 历史快照保存发送前的定义

- **约束。** 快照是脚本执行、继承认证解析之后的请求，集合里的字面量令牌会复制进每一行，重发时请求自己的脚本还会再跑一遍。
- **选择。** 快照取管线收到的定义，在脚本、继承设置与继承认证生效之前，继承认证保留 `Inherit` 哨兵。重开或再次运行时按记录的集合与文件夹现状重新解析认证，集合脚本与集合变量不参与。快照超过 256 KiB 时禁用再次运行并说明原因。“存为秘密”之后，本工作区历史里该值改写为 `{{key}}`（D-309）。
- **理由。** 历史不复制凭据，重发也不会出现重复的请求头和参数。
- **代价。** 重开的草稿再发送时，新行会带上解析后的认证；集合认证改过的话，重发用的是新认证。
- **何时重议。** 要让历史重放与原次严格一致（固定认证、带集合上下文）时。

## 70. schema 版本不符时把旧库移到一旁

- **约束。** 没有迁移，`CURRENT_SCHEMA_VERSION` 不能变；要求用户手工删除主库和 `.secrets` 容易误删秘密库。
- **选择。** 启动时把主库、`.secrets`、各自的 `-wal`、`-shm`、`-journal` 以及 `attachments` 附件目录原子地改名为 `<名称>.bak-<UTC 时间>`，任一步失败都回滚，然后新建空库，并弹窗列出每个备份文件。应用内另有“备份数据库”与“压缩”。备份在池连接上用 `VACUUM INTO` 写主库与 `.secrets`，0600 临时文件完整后再改名；压缩在 VACUUM 之后截断 WAL（D-310）。
- **理由。** 避免误删秘密库，并给出运行中拿到一致副本的途径。
- **代价。** 用旧构建打开新库时，新库同样会被移开，要靠 `.bak` 找回；备份里的 `.secrets` 副本仍是明文。
- **何时重议。** 首次对外发布前引入编号前向迁移时。

## 71. 主库 secure_delete 取 FAST

- **约束。** 性能优先，历史每次插入后都要修剪删除。
- **选择。** 主库连接设 `secure_delete = FAST`，秘密库保持 `ON`（D-311）。
- **理由。** FAST 在本来就要重写的页里把被删内容清零，不增加 I/O；ON 会为每次删除额外覆写。
- **代价。** 进入空闲页链表的页要等复用或压缩才被覆盖。
- **何时重议。** 出现取证或合规要求，或实测 ON 的开销可以接受时。

## 72. 请求、文件夹与集合的保存带内容 revision

- **约束。** 不能加列，`updated_at` 只到毫秒，标签页会话会持久化草稿。
- **选择。** 请求与文件夹的 revision 取排除身份、位置与只读字段后 JSON 的 SHA-256 前 8 字节，重启后仍有效，也不含 Webview 看不到的内容；集合沿用进程密钥哈希，因为变量里有秘密值。保存时带 revision 才检查，不带就是显式覆盖；移动与排序不算内容变化（D-312）。
- **理由。** 零 schema 改动；内容相同的 ABA 无害，恢复的标签页不会误报冲突。
- **代价。** 读取时多一次序列化与哈希；旧标签页把位置写回的问题仍在。
- **何时重议。** 需要跨设备同步冲突或字段级合并时。

## 73. 历史搜索用折叠函数与 LIKE，不建全文索引

- **约束。** 不能加 FTS 表或任何 DDL。
- **选择。** 打开 rusqlite 的 `functions` 特性，注册 `pd_casefold`（Unicode 小写）用于元数据短列。响应正文预览、响应头和已发送请求用 LIKE，只对 ASCII 不分大小写；查询含非 ASCII 时另加精确大小写的 `instr`（D-313）。
- **理由。** 不改 schema 就能搜到正文与请求头，短列也能正确折叠 Unicode 大小写。
- **代价。** 搜索是全表扫描，并在共享连接锁上进行，期间别的命令要等；正文与请求头里的非 ASCII 大小写不折叠，JSON 列按转义后的文本匹配。2026-11 的实测用 Python sqlite3 按基线 DDL 建合成库，不是 Rust 实现本身。8,500 行、每行满额 16 KiB 正文预览加 2 KiB 响应头和 4 KiB 已发送请求（约 210 MB）时，一次搜索的计数加首页约 0.55–0.6 秒，只搜元数据短列约 0.14 秒。真实正文多数远小于上限，搜索框另有防抖。
- **何时重议。** 历史量或搜索延迟成为问题时，先把历史查询挪到池连接（注册 `pd_casefold`）以免占住共享锁；允许改 schema 时改用 FTS5 外部内容索引。

## 74. 大正文缓存只按字节淘汰

- **约束。** 全应用只保留 8 个正文，远没到 64 MiB 也会淘汰；复制或保存全文时只能重发，可能是不幂等的 POST。
- **选择。** 去掉条数上限，只保留 64 MiB 总字节的 LRU（D-314）。
- **理由。** 字节才是内存的真实约束。
- **代价。** 条目可能变多，句柄查找是线性的。
- **何时重议。** 实测句柄查找成为热点时。

## 75. 同步账本复用导出文件表

- **约束。** 不能改 schema，但自动导出要分清“本机新建、还没导出”和“其他机器已删除”，分清“本机较新”和“没看过对方的改动”，停摆原因还要重启后可见。
- **选择。** 复用 `sync_export_files`，按目录记三类行：文件路径与指纹，来自导出写出的和导入时接收的文件；保留前缀 `#entity/<kind>/<key>`，记上次导出或导入时文件夹里的实体；`#status`，记上次导出结果的 JSON（D-315）。
- **理由。** 这张表本来就按目录记录本机对文件夹的认知，加行就够用，也不必在文件夹里写本机状态。
- **代价。** 一张表混放三类行，靠前缀区分。
- **何时重议。** 下一次允许改 schema 时，把实体账本和导出状态拆成独立表。

## 76. 自动导出遇到没看过的改动就停下

- **约束。** 自动导出会用本机内容覆盖其他机器写进文件夹、本机还没导入的改动和删除。
- **选择。** 自动导出遇到指纹与账本不同的新增、变更或冲突文件，以及账本里有、文件夹里没有的实体，都停下；状态行的“重试”走同一守卫。“立即导出”不受守卫约束，作为用户有意保留本地的出口。导入可以带预览令牌，文件夹变了就拒绝（D-316）。
- **理由。** 其他机器的改动在本机看过之前不会被悄悄覆盖。
- **代价。** 外部删除会一直挡住自动导出，直到用户应用删除或保留本地；导入后接收指纹意味着本机之后可以覆盖或清理这些文件。
- **何时重议。** 同步改成实体级合并时。

## 77. 凭据位置只有一个来源

- **约束。** 复制为代码、Postman 导出、文件夹同步各有一套凭据规则，查询串、URL 用户信息、表单字段与 Flow 内联步骤会以明文漏进导出文件和 Git。
- **选择。** `spanbay-model::credentials` 里的 `credential_positions` 与 `flow_step_credential_positions` 是唯一的位置来源，覆盖 URL 用户信息、凭据名的查询参数、请求头、表单字段和认证叶子；Flow 步骤按 URL 编码表单发送的请求体覆盖，按行取凭据名字段。各出口只决定在这些位置写什么：代码片段写占位变量，Postman 写空串，同步写 `{{secret:…}}`（D-317）。
- **理由。** 规则只有一处，各出口行为一致，新出口直接调用。
- **代价。** 按名字判断，会遮蔽名为 key、token 的普通参数；JSON 正文里的凭据不算位置；没选请求体类型、沿用已保存表单的 Flow 步骤覆盖不按表单读。Flow 的分享导出还没接入；Mock 导出覆盖了 URL 位置，同步里的 Mock 文档仍只按请求头名遮蔽，回调与代理 URL 的用户信息和查询值照原样写出。
- **何时重议。** 需要按值的形状识别凭据，或要覆盖正文字段时。

## 78. 同步合并单位保持为整个集合

- **约束。** 两人改同一集合里的不同请求时，整个集合最后写入者胜。按请求拆文件要新增同步实体类型、按请求存取时间戳、改写集合应用时的请求删除语义，并升到格式 v3、同时读 v2。
- **选择。** 格式保持 v2，集合连同目录和请求算一个实体，并在架构与产品文档写明（D-318）。
- **理由。** SpanBay 不提供多人协作合并（PRD §7），这项改动牵涉存储层和大部分同步测试。
- **代价。** 同一集合的交叉编辑只能整体二选一，而且会以冲突的形式让自动导出停下。
- **何时重议。** 出现多人共享同一个同步目录的需求时，按请求拆文件、升到 v3，并保留对 v2 的读取。

## 79. Mock 模板用自实现的有界 Handlebars 子集

- **约束。** 锁文件里没有 handlebars 类模板库；Mockoon 模板需要块助手、子表达式与 faker、date；渲染结果直接作为本机监听器的响应，必须有硬上限。
- **选择。** 在 `spanbay-workbench` 里自实现解析与渲染，支持 repeat、each、if、unless、else、子表达式与 `key=value` 选项。输出上限 1 MiB，嵌套 16 层，单块循环 1000 次、总计 10000 次。不认识的助手原样输出，导入时逐个列出；faker 映射到现有的 `$random*` 动态变量（D-319）。
- **理由。** 引入 handlebars 之后仍要自己补 Mockoon 专有助手与资源上限，收益有限；自实现规模可控，上限可测。
- **代价。** 只覆盖常用助手，Mockoon 的 setVar、switch 等不支持，要按需扩充。
- **何时重议。** 导入的模板大量依赖未支持的助手，或出现成熟、带资源上限的 Rust 模板库时。

## 80. Mock 额外允许的主机只放宽 Host 校验

- **约束。** Android 模拟器（10.0.2.2）与 Docker Desktop（`host.docker.internal`）的请求经回环到达，带的 Host 却被防 DNS 重绑定的校验拒绝；`mock_servers` 表没有可用的列。
- **选择。** 新增 `mock.extra_allowed_hosts`，经允许补丁指名的字段登记，只留在本机。带端口的条目只认该端口，不带端口的认绑定端口，界面添加前要确认。监听仍只绑 127.0.0.1；本机有 IPv6 时同一端口另绑 `[::1]`，它被别的进程占用就按端口冲突报错（D-320）。
- **理由。** 默认安全不变，例外要用户确认；补绑 `[::1]` 后，把 localhost 先解析成 `::1` 的客户端不会连到别的进程。
- **代价。** 列表对所有 Mock 服务生效，不能按服务设置；Linux 上的 Docker 经网桥地址访问时仍要绑定非回环地址，这里不支持。
- **何时重议。** 需要按服务设置例外，或要支持局域网访问时。

## 81. Mock 录制只在内存里

- **约束。** 从日志存为路由只有 64 KiB 预览；schema 不能改，没有地方持久化录制开关与内容。
- **选择。** 每台运行中的服务有一个运行时录制开关。开启期间完整保留每个转发响应，最多 200 条、合计 32 MiB，同一方法与路径以最新为准，停止即清空。用户主动“存为路由”时，只为还没有路由应答的请求加路由，非 UTF-8 正文存成 Base64；录制过的日志行取完整正文，否则标明截断（D-321）。
- **理由。** 不改 schema，内存有上限；存为路由走前端的草稿与保存流程，不和自动保存冲突。
- **代价。** 重启应用或停止服务后录制丢失，开关不保存。
- **何时重议。** 需要跨会话保留录制，或按查询参数、请求体区分录制时。

## 82. Mock 正文支持 Base64 与本地文件，上游超限返回 502

- **约束。** 转发时请求体按有损 UTF-8 处理，二进制会损坏；上游正文超过 1 MiB 时被静默截断；Mockoon 的 FILE 正文无法表示。
- **选择。** 请求体与转发正文全程按字节处理，上游超过 1 MiB 时返回带原因的 502。`MockResponse` 新增 `body_source`，取 Base64 或 File。File 的正文存绝对路径，每次请求读取，必须是不超过 1 MiB 的普通文件，路径不渲染模板，读不到时返回 500 并写明原因（D-322）。
- **理由。** 截断后还声称成功会误导客户端；路径不模板化，请求就操纵不了读哪个文件。
- **代价。** 导入的配置可以让本机 Mock 提供任意本地文件，好在服务只听回环、默认不启动；相对路径要用户改成绝对路径。
- **何时重议。** 需要大于 1 MiB 的正文，或要把文件访问限制在某个目录时。

## 83. Mock 用 Prefer 头强制选响应，并提供响应级故障

- **约束。** OpenAPI 生成的 4xx、5xx 响应永远选不中；断连与挂起只对 SSE 有效。
- **选择。** 请求带 `Prefer: code=<状态码>` 时，直接返回该状态码的第一个响应，不看规则与模式，日志的选择原因记为 prefer；没有这个状态码的响应就照常选。响应可以设故障，都在延迟之后执行：挂起保持连接不响应，直到 60 秒或停止服务；断开不发任何字节直接关连接。Demo 的选择规则同步支持 Prefer（D-323）。
- **理由。** 与 Prism 的约定一致，不改路由就能测错误分支。
- **代价。** Prefer 盖过规则，可能和用户期望的规则顺序不一致；按 OpenAPI 校验请求、规范变更后重新同步都没做。
- **何时重议。** 需要按 example 名称选响应、做请求校验或重新同步时。

## 84. Flow 与集合运行里局部变量的生存期

- **约束。** Postman 里 `pm.variables` 在一次迭代内跨请求可见；集合运行每个请求都清空局部变量，Flow 也不把脚本写的局部变量交给下一步，未解析扫描却把 `pm.variables.set` 算作已定义。
- **选择。** 集合运行的局部变量在一次迭代内跨请求保留，每次迭代从空开始。Flow 的局部变量就是 flow 变量，一次运行内跨步骤保留：步骤结束后，脚本留下的新增、修改与 unset 合并回去，抽取值在其后覆盖，机密标志保留；运行结束即丢弃，不写库。单次 Send 仍是一个请求一份局部变量（D-324）。
- **理由。** 与 Postman 一致，登录步骤里 `pm.variables.set` 之后，后续步骤能用 `{{x}}`，也与未解析扫描的判定一致。
- **代价。** 同一迭代里前面请求的局部值可能遮住后面请求的环境同名值；没有机密标志的局部值照常写进历史。
- **何时重议。** 要支持跨迭代保留，或在单次 Send 之间共享局部变量时。

## 85. Flow 条件表达式用有界小语言

- **约束。** 条件靠切字符串求值，不支持的运算符退化成真值判断（`{{count}} > 10` 恒为真），引号里的关键字被误切，保存时不校验，被跳过的步骤也要白等 delay。
- **选择。** 自写有界递归下降解析器，支持比较运算与 contains、and/or/not 及符号写法、括号和单双引号字面量，上限为 1024 字节、128 个记号、16 层嵌套。先解析后填变量；`==` 与 `!=` 两边都是数字时按数值比较，否则按原文比较；`>` 等运算两边必须是数字，否则该步失败。条件在 delay 之前求值，保存时就校验（D-325）。
- **理由。** 语法极小，通用表达式引擎（如 evalexpr）既过度又难设上限，几十行的有界实现更可控。
- **代价。** 裸写多词或 `a==b` 形式的右值要加引号，已存的这类条件会在运行时让步骤失败；`007 == 7` 为真。
- **何时重议。** 需要函数调用、正则匹配或 JSONPath 引用时。

## 86. Flow 提取值默认按凭据规则定机密

- **约束。** 提取的变量固定是非机密，令牌用在后续步骤的 URL、请求头或正文时会再次明文写进历史。
- **选择。** `FlowExtraction` 增加可选的 `secret`。未设置时，凭据名、Cookie 来源与凭据请求头来源默认是机密，凭据名与 `is_secret_header_name` 同一规则。机密提取值作为机密局部变量参与执行，执行器在发送记录里打码；同名的初始变量也按机密处理，运行摘要不保存机密值。前端复选框镜像同一默认规则（D-326）。
- **理由。** 凭据最常见的流向就是从登录响应流到后续请求，默认机密能堵住第二次落库，又不用逐项设置。
- **代价。** 登录步骤自己的响应正文仍原样入库；名字不像凭据的令牌要手动勾选；前后端各有一份默认规则，要保持一致。
- **何时重议。** 引入统一的“凭据位置与流向”模型，或历史正文按凭据字段脱敏时。

## 87. Flow 部分运行的种子存进运行摘要

- **约束。** “只运行此步”和“运行到此”的种子只在内存里，重启后必须完整重跑；不记录上次运行的环境，换环境后会带入旧环境的令牌；schema 不能改。
- **选择。** `flow_runs.summary_json` 增加 `environment_id`、`variables` 与 `withheld_variables`。`variables` 只存非机密、没被脱敏规则命中、不超过 4 KiB 的值，最多 100 个；`withheld_variables` 记没存值的名字。部分运行优先用本次会话的最新结果，其次用最新的存储摘要；上次运行的环境与本次不同时一个变量都不带入并提示。Cookie 不继承（D-327）。
- **理由。** 复用 JSON 列，不改 schema；按环境隔离，避免把生产令牌带进别的环境。
- **代价。** 重启后机密值（通常是令牌）仍要完整重跑才能拿回；摘要略大。
- **何时重议。** 要把 Cookie 罐或机密种子存进秘密库，以便重启后直接续跑时。

## 88. Flow 请求体覆盖保留类型，内联步骤可编辑完整请求

- **约束。** 内联步骤只能填方法和 URL；从已保存请求切到内联只拷贝方法和 URL，隐藏的覆盖项照样生效；正文覆盖会把表单和 GraphQL 变成 `text/plain`。
- **选择。** `FlowStep` 增加可选的 `body_override_kind`。未设置时保留原请求体类型：JSON、原始文本语言、表单按 `name=value` 行、GraphQL 只替换 query，只有无正文、多部分与二进制才变纯文本。内联步骤可编辑查询参数、请求头、请求体与类型。切换到内联时复制完整请求并合并覆盖项，GraphQL 转成等价的 JSON 载荷，多部分与文件请求体不复制并提示（D-328）。
- **理由。** 覆盖只改内容、不改类型，界面上没有看不见却仍生效的配置。
- **代价。** 多部分与二进制请求体仍不能内联；内联步骤不继承集合的认证与脚本。
- **何时重议。** 需要在内联步骤里支持多部分、文件或认证配置时。

## 89. 测试台状态增加“未观察到”

- **约束。** 模型正常回答却没表现出工具调用、推理、缓存命中或搜索时，存储层记“未观察到”，单元格却显示“不支持”或“响应无效”。前者是终态、不重测，后者计为失败，都与 §3 的“没观察到的能力不记为不支持”冲突。
- **选择。** `ProbeStatus` 增加第九个状态 `NotObserved`，与 `derive_capability` 共用一套判定，细化 D-44 的状态集合。它不算失败，“重试失败”会再跑这类单元格，不写“不支持”，也不过滤路由（D-329）。
- **理由。** 能力存在却不一定在一次样本里表现出来，判成终态会把能用的模型挡在路由外。
- **代价。** 状态词、图例、导出和统计多一类，前端映射表必须同步。
- **何时重议。** 引入多样本统计或置信度后，可以按次数把“未观察到”升成“不支持”。

## 90. 能力检查遇到 400 或 422 记为请求被拒

- **约束。** Tools、JSON schema、Vision 等检查遇到 400、415、422、501 都记“不支持”，再经 Apply 进入路由过滤；中转站常因参数不兼容回 400，误判会让模型被路由跳过。
- **选择。** 任何检查的 400 与 422 记为“响应无效（请求被拒）”，不写能力事实；只有 415、501，或没有 2xx 的协议不符才记“不支持”。Tools 检查第一步调用了工具即记支持，回传那一步失败只写进明细。Apply 里“改成不支持”默认不勾，并列出原值、依据的密钥、HTTP 状态和受影响的备用链（D-330）。
- **理由。** 没有正面证据时宁可不下结论，也不悄悄缩小路由。
- **代价。** 确实不支持却回 400 的服务商要用户手动设定能力。
- **何时重议。** 积累到可靠的服务商错误体指纹（例如明确的 unknown tool type）时，可以按指纹判“不支持”。

## 91. Apply 按上次应用之后的证据生成计划

- **约束。** Apply 只读最近一次运行，在模型页单测一个模型就会顶替测试台的整轮运行，那批结果再也无法应用，网格所见与 Apply 对不上。
- **选择。** 计划读该服务商每把密钥在各单元格上的最新结果，只取晚于最近一次已记录应用、且不超过 7 天的结果，扫描留下的密钥检查不算。撤销会删掉应用记录，原先的证据重新算作未应用。最近一次应用时间从现有应用日志 JSON 读取，不改表（D-331）。
- **理由。** 网格所见即 Apply 所应用，用户不用挑运行。
- **代价。** 应用日志只保留各服务商共用的最近 5 条，较早的应用被挤出后，更旧的证据会在 7 天内再次被提出；计划只列与现状不同的项，影响有限。
- **何时重议。** 要精确追踪“已应用”时，再考虑给结果记应用标记，这需要改 schema。

## 92. 没读过模型列表的密钥只服务无人列出的模型

- **约束。** 没读过列表的密钥默认能调所有模型，新密钥属于中转站另一分组时会调到不属于它的模型；读列表只靠前端补读一次。
- **选择。** 路由里，没读过列表的密钥只服务当前没有任何密钥列出的模型，读过列表的规则不变，细化 D-258。新增或换值的密钥保存时由核心排队读取列表，读到之前密钥行一直标“未读列表”（D-332）。
- **理由。** 分组归属未知时，不抢别的分组已确认的模型，也不让只有一把密钥的服务商断供。
- **代价。** 新密钥在读到列表之前能调的模型少于实际范围；没有列表端点的服务商不受影响。
- **何时重议。** 中转站提供按密钥查询分组的接口时，改用分组直接判定。

## 93. 中转站倍率与币种存进 quirks JSON

- **约束。** 不能改 schema，`provider_pricing` 表没有倍率和币种列；中转站的费用一律按官方价算，扫描得到的声明价被丢掉。
- **选择。** quirks 新增 `relay_pricing`，含倍率与币种；倍率大于 0 且不超过 1000，币种限于支持的六种。价格解析出结果后，除服务商自己的模型价格行外，各级价格都乘以倍率并换成该币种，价格依据里注明。扫描时同时声明输入与输出价的模型，添加服务商时存为 custom 价格行，行时间取扫描时间；重新扫描补上还没有价格行的模型，并更新行时间仍等于上一次扫描时间的 custom 行，用户改过的行不动（D-333）。
- **理由。** 复用现有 JSON 列与价格表；quirks 本来就随服务商导出、同步和校验。
- **代价。** quirks 原本只放协议差异，现在多一项计费语义；不支持按分组定价；f64 字段靠手写 Eq，靠校验排除 NaN。扫描存的行靠时间戳与用户的行区分：主机某次不再声明某模型的价格时，这一行留下，之后按用户的行对待。
- **何时重议。** 下一次改 schema 时，把倍率挪到 `provider_pricing` 的独立列，并支持按分组定价。

## 94. 余额刷新按失败类型退避

- **约束。** 余额刷新不分失败类型，瞬时失败要等满一个间隔，永久失败无限重试，也不读 Retry-After；发请求前的失败（如 CA 文件缺失）被吞掉。
- **选择。** 瞬时、网络与 429 失败 5 分钟后重试，鉴权、找不到接口这类要用户处理的失败至少隔一天。429 的 Retry-After 存为 `retry_at_ms`，对自动刷新和打开服务商时的检查都生效。先判断到期再构建传输，构建失败记为密钥的 Blocked 错误（D-334）。
- **理由。** 失败恢复更快，永久失败不反复打扰服务商。
- **代价。** 永久失败修好后，要靠手动刷新、打开服务商或等满一天才会再查。
- **何时重议。** 用户反馈修好密钥后余额迟迟不更新时，可以在密钥或配置变更时清除退避状态。

## 95. LLM 后台任务共用取消令牌，目录同步按到期唤醒

- **约束。** 目录同步固定 6 小时计时，完成后界面不刷新，也没有取消和单飞；余额调度与添加后的余额刷新各自游离。
- **选择。** 目录同步睡到下次到期（最长 6 小时），改间隔或手动同步后唤醒，成功后推送 `CatalogChanged`，设置页的模型目录显示期间订阅它并在流断档后重读。目录同步、余额调度和添加后的余额刷新挂在同一个后台取消令牌下；目录同步双向单飞（自动同步遇到运行中的同步就跳过这次检查，手动同步遇到时返回冲突错误），余额靠已有的每密钥 30 秒节流去重（D-335）。
- **理由。** 关闭时不留游离任务，目录变化能及时到达界面。
- **代价。** 自动同步运行时点“立即同步”只得到一条“正在同步”的错误，要等它结束再点；后台同步完成后目录列表回到第一页。
- **何时重议。** 后台任务种类继续增加，需要统一的任务调度时。

## 96. 网关跨协议的未登记字段默认拒绝

- **约束。** PRD 要求无法承载就拒绝，而未登记字段被可见丢弃后模型仍会“成功”作答，典型是会话引用 `previous_response_id`、`conversation` 与 Gemini 的 `cachedContent`。
- **选择。** 字段表未登记的字段跨协议一律拒绝该目标，只放行显式标为 SafeDrop 的字段，会话引用类字段按名列入 Refuse。Codex、Claude Code 与常见 OpenAI SDK 发送的无害字段补进 SafeDrop，例如 `include`、`prompt_cache_key`、`safety_identifier`、`truncation`、`top_logprobs`、`safetySettings`（D-336）。
- **理由。** 宁可让客户端看到明确的 400，也不让缺上下文的回答冒充成功。
- **代价。** 客户端发了还没登记的新字段时，跨协议请求会被拒，要补表；同协议直通不受影响。
- **何时重议。** 频繁出现因新增无害字段被拒的报告时，考虑按协议版本批量登记，或给一个按字段放行的开关。

## 97. 网关为跨协议的 Messages 目标合成缓存断点

- **约束。** Chat、Responses、Gemini 客户端没有 `cache_control`，经 hub 转到 Anthropic 时每轮都不缓存，成本明显偏高。
- **选择。** 目标是 Messages、请求没有断点、该服务商本会话也没拒绝过缓存提示时，在系统提示与工具之后、最后一条消息之后各放一个断点。带 `pdk1.` 标记的同协议请求只剥掉外来签名块，仍按直通处理。轮询策略按对话前缀（系统提示加首条消息的哈希）记住起步密钥（D-337）。
- **理由。** 这两个断点对多轮对话收益最大，也不改变语义。
- **代价。** 低于最小缓存长度的请求上，断点会被上游忽略；拒绝 `cache_control` 的第三方 Messages 兼容端点要等进入会话内的拒绝名单。
- **何时重议。** 上游对 `cache_control` 报错，或需要按服务商关闭合成时。

## 98. 429 冷却按密钥与模型计

- **约束。** 限流通常只针对单个模型，整把密钥冷却会让同一密钥上的其他模型被错误跳过。
- **选择。** 限流只让该密钥在该模型上休息，按 Retry-After 或逐次加倍；余额、鉴权与地区失败仍让整把密钥冷却。单次请求内，限流也不让后续组跳过这把密钥。全部候选失败且以 429 或 503 结束时，响应带 Retry-After：先取上游值，否则取计划内最早结束休息的时间（D-338）。
- **理由。** 贴近上游真实的限流单位，客户端也知道何时重试。
- **代价。** 账户级的并发限流若被上游报成普通 429，会对每个模型各试一次。
- **何时重议。** 发现某厂商的 429 实际是账户级时，在词表里把它归为账户级。

## 99. 未知模型名映射改为显式开关

- **约束。** PRD 要求没有别名、展示请求名与实际目标，Connect 却为 Claude Code 隐式开启映射，拼错或退役的模型名会被悄悄替换。
- **选择。** 映射默认关，只能在客户端的「限额」面板里显式开启。开启时请求体保留原名，只改路由，日志记原请求名，响应带 `x-spanbay-model-mapped`（D-339）。
- **理由。** 正常的档位流量已由写入的模型覆盖，映射只该处理少数例外。
- **代价。** 依赖隐式映射的 Claude Code 客户端，后台档位名会返回 404，要用户打开开关或重新连接。
- **何时重议。** Claude Code 的档位命名再次变化时。

## 100. 逐客户端限额存在现有 JSON 列

- **约束。** 不能改 schema。
- **选择。** 限额写进 `llm_gateway_clients.allowed_aliases_json`，含 RPM、同时请求数、日与月预算、日与月 token、到期时间；有限额时存成 `{aliases, limits}` 对象，没有时还原为纯数组。检查顺序固定为过期 401、预算或 token 402、分钟窗口 429、并发 429。预算读用量汇总，每个客户端最多每 10 秒读一次，只累计与预算同币种的成本，价格未知的调用只计 token（D-340）。
- **理由。** 不改 schema 也能实现，并复用现成的用量汇总。
- **代价。** 列名与内容含义不完全一致；日志异步落库加缓存，预算约有 10 秒滞后。
- **何时重议。** 下一次允许改基线 schema 时，改为独立列。

## 101. 首次连接打开网关自启，并提供不轮换令牌的“更新地址”

- **约束。** 写进工具的是写入当时的地址快照，网关默认不随应用启动，改端口后每次 Connect 又会轮换令牌。
- **选择。** 本数据目录第一次 Connect 成功后自动打开 `ai.gateway.enabled_on_start`，之后不再强制。配置漂移的工具提供“更新地址”：读取文件里现有的令牌，核对它属于活动客户端，只重写地址并记一条账本（D-341）。
- **理由。** 不用额外问答，连接在重启后仍然可用。
- **代价。** 自动改了一个用户可见的设置，Access 页的开关仍可以关掉。
- **何时重议。** 用户反馈不希望网关自启时，改为在 Connect 结果里询问。

## 102. completions 与 rerank 只做非流式直通

- **约束。** `/v1/completions` 与 `/v1/rerank` 没有 hub 模型，转码不可行。
- **选择。** 只改 model，原样转发到目标 OpenAI 风格端点旁的同名路径，沿用规划、故障转移与日志；流式 completions 返回 400，提示改用非流式（D-342）。
- **理由。** 以最小代价覆盖 FIM 与重排序的主要用法。
- **代价。** 依赖流式补全的编辑器插件暂时用不了。
- **何时重议。** 需要支持流式 FIM 时，增加不经解码器的原始字节流管道。

## 103. 客户端配置 JSON 用 jsonc-parser 原位编辑

- **约束。** Gemini CLI 与 OpenCode 的配置允许注释和尾逗号，用户还会自己排键序；serde_json 默认按字母序输出，`preserve_order` 又是依赖图级特性，会改变整个工作区的 JSON 输出顺序，§21 不采用。
- **选择。** `spanbay-client-config` 引入 `jsonc-parser`（`cst` 与 `serde` 特性）解析 JSONC，在具体语法树上只替换变化的值，新文件仍以 2 空格缩进写出；`FilePlanDto` 去掉“重新格式化”相关字段（D-343）。
- **理由。** 库成熟，dprint 与 Deno 在用，没有新增传递依赖；注释、键序与缩进都保留，预览差异里只有 SpanBay 写的改动。
- **代价。** 多跟进一个依赖的版本；同一对象里有重复键时，语法树改的是第一个，serde 读到的是最后一个。
- **何时重议。** `jsonc-parser` 停止维护，或语法树 API 出现破坏性变更时。

## 104. 客户端配置原件在重新接管时刷新，恢复整组确认

- **约束。** 原件只在第一次写入时保存，几个月后“恢复原配置”会抹掉用户在此期间的修改；Gemini 的两个文件逐个恢复时，取消确认会只恢复一半；schema 不能改。
- **选择。** 工具配置里没有 SpanBay 连接时视为重新接管，即没有网关形令牌，也不是“回环地址加令牌”；这时把它全部文件的当前内容刷新为原件，写入失败就放回旧原件。两种恢复都先读齐所有文件与备份：要确认时一个字都不写，返回每个文件的差异和“将删除”标记；写到一半失败就把已恢复的文件写回。“断开”即恢复原配置（D-344）。
- **理由。** 原件始终是用户最近一次自己的配置，确认框能看到每处改动和要删的文件。
- **代价。** “已接管”靠启发式判断，用户自己带令牌的回环代理会被当作已接管而不刷新原件；断开会连同接管期间的手改一起退回，差异里看得到。
- **何时重议。** 需要精确的接管记录时（可以是数据目录里的标记文件，不必改 schema），或用户要求只撤掉 SpanBay 写过的键时。

## 105. 客户端账本与备份的保留

- **约束。** 备份按 5 份修剪而账本不修剪，连续几次“恢复上一次配置”就会因备份缺失而失败；原件与备份明文保存用户凭据且永不过期。
- **选择。** 账本每个工具保留最近 5 次写入，加上每个客户端对该工具的最近一次写入。账本引用的备份不修剪，其余按文件与种类（写入备份、安全备份）各留 5 份，超过 30 天删除，由 `spanbay-app-llm` 在账本变化后触发。删除客户端时删除它的账本行，另有“删除副本”入口，只保留最近一次写入的备份；删除副本后，在配置重新变回用户自己的内容之前，写入不再保留原件，避免把 SpanBay 写入的内容当成原配置（D-345）。改地址与服务商改名的重写写入同样在记账后修剪。
- **理由。** 恢复链不会因修剪而断开，凭据副本有上限和清除入口。
- **代价。** “恢复上一次配置”最多回退 5 次写入。
- **何时重议。** 用户需要更长的恢复历史，或要求凭据副本默认不保留时。

## 106. 令牌轮换前先对账

- **约束。** 陈旧的账本行会让轮换永久失败；别的客户端覆盖同一工具后，旧客户端的行描述的已经不是当前文件。
- **选择。** 轮换前先拿账本与文件对账，文件里已经没有旧令牌的行跳过、列出，并在提交后删除。别的客户端覆盖同一工具时，旧客户端的行保留（D-346）。
- **理由。** 轮换不被陈旧行卡住；保留旧客户端的行，是为了恢复到它那次写入之后，账本仍如实描述文件。
- **代价。** 轮换时要多读一遍各个文件。
- **何时重议。** 账本改成按文件精确记录令牌归属时。

## 107. 长工具链按工具步骤修剪与压缩

- **约束。** 修剪与压缩以用户轮为保护单位，一条消息驱动的长工具链在同一回合里既剪不动也压不了，最后只能以“上下文已满”结束；表结构不能改。
- **选择。** 修剪保留“最近 2 轮”与“最近 4 个工具步骤”中消息更少的一段。保留轮次之前只剩旧摘要时，压缩把切点移进当前回合，保留最近 4 个步骤，切点落在步骤边界；摘要末尾原样附上这一回合的用户请求，同一回合再压缩时沿用。超限后的应急缩短覆盖最后一条用户消息之后的全部工具结果，“立即压缩”是否可用由核心按同一规则算出（D-347）。
- **理由。** 长工具链才是撑满窗口的主要来源，按步骤切分不需要新存储。
- **代价。** 当前回合早期步骤的原文只剩摘要，用户请求最多原样保留 8000 字符；应急缩短会打乱这一回合的缓存前缀。
- **何时重议。** 按 token 预算选择保留段，或改成存储端截断时。

## 108. 窗口未知时工具结果预算按 128k 计

- **约束。** 窗口未知时单条结果给满 256 KiB，单轮总量不设上限，超限错误里得知的窗口也不参与预算。
- **选择。** 单条与单步结果预算统一用本次运行的窗口：优先取超限错误报出的窗口，其次是模型自报的窗口，都没有时用 `UNKNOWN_WINDOW_TOKENS`，即 128,000（D-348）。
- **理由。** 与修剪、压缩的兜底取值一致，避免在未知的小窗口模型上一次塞爆。
- **代价。** 未登记窗口的大模型，单条结果从 256 KiB 降到约 40 KiB，超出部分要用 `read_output` 翻页。
- **何时重议。** 服务商目录普遍报出窗口，或改用实测分词器时。

## 109. 探测工具按估算计入运行费用上限

- **约束。** `run_probe` 与经网关的 `send_request` 都不计入单次运行的费用上限；探测单元格只有 token，没有逐格价格。
- **选择。** `run_probe` 运行前用测试台同一份估算，结束后按已完成单元格的占比，把各币种金额计入运行与父运行的费用上限和成本账本。经网关的发送不计（D-349）。
- **理由。** 估算本来就是批准卡上用户看到的数字；网关日志只按客户端令牌记账，认不出发起请求的运行，按时间窗归属会把别的客户端的流量算进来。
- **代价。** 计入的是估算，不是实际花费；运行记录上的费用数字仍只含模型调用。
- **何时重议。** 网关能在日志里带上运行标识，或探测结果带上逐格费用时。

## 110. shell 显式远端命令套用抓取的出处规则

- **约束。** Full access 下沙箱网络全开，`curl`、`ssh`、`git push` 绕过“出处不明的主机仍询问”；本地出站代理的工作量大。
- **选择。** 解析命令行里显式联系远端的命令：`curl`、`wget`、`nc`、`ssh`、`scp`、带远端的 `rsync`，以及 git 的推拉与克隆。点名的主机有任一没在用户消息、附件、搜索结果或已批准调用里出现过，或命令根本没写主机，就强制询问（`shell_remote`）；跑过的命令所点名的主机随后算作见过。这些网络客户端同时标为高风险（D-350）；只点名回环主机（`localhost`、`127.0.0.0/8`、`::1`）且不带代理、改址或配置文件选项的 `curl`、`wget` 除外，本地服务的健康检查因此仍能建“总是允许”规则。
- **理由。** 成本低，覆盖最常见的外传路径，与 `fetch_url` 用同一套规则。
- **代价。** 尽力解析，看不到脚本或解释器里的联网；`git push` 每次都要询问。
- **何时重议。** 沙箱只连本地出站代理、按主机放行之后，改由代理统一执行。

## 111. 未受信任文件夹的文件与命令输出加外部数据信封

- **约束。** 外部数据信封按工具决定，克隆仓库里的文件内容和命令输出以普通工具结果进入上下文，与“未受信任文件夹不注入指令”脱节。
- **选择。** 文件夹未受信任时，`read_file`、`grep`、`glob`、`list_dir`、`shell` 与 `shell_output` 的结果先显形隐藏字符，再包进外部数据信封（D-351）。
- **理由。** 信封跟着数据来源走，与指令注入规则一致。
- **代价。** 未受信任文件夹里的结果多出信封标签，占少量 token。
- **何时重议。** 按单个文件或子目录记录信任状态时。

## 112. 删除与移动文件进改动表，不改表结构

- **约束。** 没有删除和移动工具，只能走 shell，不进改动日志也撤销不了；`agent_file_changes` 的 kind 只允许 create 与 edit，schema 不能改。
- **选择。** `delete_file` 记成一行写后哈希为空的 edit，原始字节照常进附件存储，文件仍不存在时撤销按原样写回。`move_file` 记成目标的一行 create 加源文件的一行删除，两行各自撤销。只处理不超过写入上限的普通文件，移动不覆盖已有文件，两者都逐次审批，不给记住的规则。`edit_file` 增加 `edits` 数组，一次改多处，任何一处失败整次不写（D-352）。
- **理由。** 复用现有日志、撤销与崩溃恢复，不需要迁移。
- **代价。** 移动不保留执行位；一次移动在改动页里显示为两行；不能删除文件夹。
- **何时重议。** schema 能增加删除与移动类型，或需要整轮回滚时。

## 113. MCP 协议面在自研客户端里补齐常用部分

- **约束。** 只实现了 tools，通知一律丢弃，超时写死 120 秒，没有 resources；改用 `rmcp` 要连带升级 RustCrypto 0.11，`rmcp` 还是 0.x；把超时存进 `McpTransportConfig` 会波及十几个文件。
- **选择。** 继续自研。工具列表变更通知让缓存过期；`tools/call` 带 `progressToken`，每次进度通知重新计时，总时长上限 30 分钟。按服务器的超时用设置 `ai.agent.mcp_call_timeout_s`，以服务器 id 为键，取 5 至 3600 秒。声明了 resources 的服务器多一个只读的 resources 工具；prompts、roots、HTTP 推送流与 OAuth 不做（D-353）。
- **理由。** 覆盖长任务与工具变更这两类最常见的失败，不加新依赖。
- **代价。** 需要 OAuth 的服务器只能在请求头里放令牌；prompts 不能用。
- **何时重议。** 要做 MCP OAuth 或推送流，或 `rmcp` 发布 1.0 时。

## 114. 智能体改过的请求在批量运行前统一检查

- **约束。** 集合运行与 Flow 只有一个回答生产守卫的 `confirmed` 标志；运行前对话框列不出逐条的目标主机。
- **选择。** 运行前用单发同一套策略检查所有将运行的请求：展开继承认证，按不含该请求自身的声明主机判断。遇到智能体改过、且会把凭据发往未声明主机的请求就整次拒绝（Validation），列出请求名和主机，提示先在请求模块单发一次复核；`confirmed` 不能绕过（D-354）。
- **理由。** 不改 DTO 和前端就能堵上凭据外泄，单发的确认卡本来就写出了主机。
- **代价。** 一条没复核的请求会挡住整次运行。
- **何时重议。** 前端运行对话框能逐条展示智能体改过的请求与目标主机时，改为在运行前确认里合并询问。

## 115. 智能体标记的清除条件与按环境声明主机

- **约束。** 已保存请求的主机对所有环境生效，用户点一次发送就无条件清除标记，智能体可以借一个不带凭据的 GET 把任意主机变成已声明主机；schema 不能改。
- **选择。** 只有目标主机不靠该请求本身就已声明，或用户在确认卡上看到并接受了目标主机，才清除标记；不带凭据去未声明主机的发送照常发出，但标记保留。另一个环境声明而本环境没声明的主机，不因有已保存请求指向它就算本环境已声明（D-355）。
- **理由。** 清除标记等于授予声明权，必须让用户看到主机；排除别的环境的主机不需要新存储。
- **代价。** 智能体建的无凭据请求会一直带标记，直到用户确认过一次带凭据的发送或手动声明主机。
- **何时重议。** 需要逐请求、逐环境记录声明来源时。

## 116. 智能体发送使用每次运行独立的 Cookie 罐

- **约束。** 智能体发送读写用户的工作区 Cookie 罐，会带上或替换用户的登录会话，而 Cookie 不算“携带的凭据”。
- **选择。** 智能体的 `send_request` 不读也不写工作区 Cookie 罐。每次运行在内存里有自己的罐，同一运行后面的发送带上前面响应设置的 Cookie，运行结束即丢弃；智能体来源一律不持久化 Cookie（D-356）。
- **理由。** 与 Flow 的隔离一致，信任度更低的智能体不应比 Flow 权限更大；同一运行内先登录再调用的流程仍然可用。
- **代价。** 智能体用不了用户已有的会话，需要会话时得在同一运行里先登录。
- **何时重议。** 用户需要显式授权智能体按声明主机只读使用工作区 Cookie 时。

## 117. 智能体新建请求的写入进改动表

- **约束。** `create_request` 的目录、请求、标记三次写入不在一个事务里，不进改动记录也撤销不了；schema 不能改。
- **选择。** 四步写入放进一个事务。改动行复用 `agent_file_changes`，folder 写 `spanbay-request://<工作区>/<请求>`，before blob 是写入前的请求 JSON，after blob 是写入后的请求与新建的目录。撤销时请求仍是写入后的样子才恢复（含原标记），或删除新建请求和重新变空的新建目录，否则报冲突。改动行插入失败或没有 blob 存储时，写入照常完成，并在结果里注明没有记录（D-357）。
- **理由。** 复用现有的保留、撤销与差异管道，不加表也不加列。
- **代价。** 前端要识别这种 folder 前缀，差异视图显示的是请求 JSON。
- **何时重议。** 冲突判断改用请求的内容 revision（D-312）时。

## 118. 命令造成的文件改动只列出，不承诺能撤销

- **约束。** 改动表只覆盖文件工具，shell 与 MCP 改的文件撤销不了，界面文案却暗示整轮可撤销；影子 git 快照要重议 D-283。
- **选择。** 运行里第一次调用进程类或 MCP 工具之前列一次文件夹清单，含路径、大小与修改时间，遵守 `.gitignore`，最多 20000 个文件；运行结束再列一次。不被改动表覆盖的新建、修改与删除文件，用 `untracked_changes` 通知列出数量和前 5 个路径（D-358）。
- **理由。** 只读元数据，成本有界，不保存内容，也不需要 git。
- **代价。** 用户在运行期间自己改的文件也会被列进来；超过上限的文件夹不检查；按修改时间和大小判断，同尺寸同时间戳的改动发现不了。
- **何时重议。** 决定做影子快照或整轮回滚时。

## 119. 回放环里命令输出的上限

- **约束。** 回放环 4096 个事件、1 MiB，按队首淘汰，大量 shell 输出会把审批卡等结构性事件挤出去；回放依赖连续序号，单独保留个别事件会变成缺口。
- **选择。** 单个调用的实时输出最多推送 256 KiB，之后只发一条提示；回放环折叠旧的命令输出时，每段只留最后 16 KiB。完整输出仍在调用结果和落盘文件里（D-359）。
- **理由。** 不改回放序号契约，用输出上限给结构性事件留出空间。
- **代价。** 超过上限的实时输出在实时视图里看不到，要看调用结果；回放到的旧输出只剩尾部。
- **何时重议。** 回放协议支持按事件类型保留时。

## 120. 对话上下文分段存储，正文转义结束标记

- **约束。** 上下文以带标签的文本存在用户消息里，库表不能改；模型收到的文字要保持一致。
- **选择。** 核心把每个上下文存成独立的文本段，正文里的 `</context>` 转义成 `<\/context>`。前端只把“整段恰好是一个标签块”的文本段读成芯片，从不在用户自己写的文字里切芯片。编辑过的消息文字与标签块合在一段，旧数据里的正文也可能没转义，这两种情况退回按块边界切分（D-360）。
- **理由。** 不改 schema，响应正文伪造不出芯片，旧会话照样能读。
- **代价。** 模型看到的正文里结束标记写成 `<\/context>`；编辑过的消息仍是合并格式。
- **何时重议。** 编辑接口改为分段传上下文时，去掉合并格式的兼容读取。

## 121. 删除回合前先预览后果

- **约束。** 核心删除整棵子树，包括其他分支和这些运行的改动记录，删了就不能再撤销那些改动。
- **选择。** 确认前总调用核心预览，结果新增 `pending_file_changes` 与 `branches`（叶子数）。有待复核的改动时，默认按钮是“复核改动”，删除要明确点“仍然删除”（D-361）。
- **理由。** 用户看清全部后果之前不会误删可撤销的改动。
- **代价。** 每次删除多一次 IPC，确认框文字更长。
- **何时重议。** 改动日志与消息解耦、删除不再连带删掉日志时。

## 122. 审批卡折叠行只对完整可见的单行命令给“允许一次”

- **约束。** 关卡区空间不够时卡片折叠成一行，用户只能看到这一行。
- **选择。** 只有一行能完整显示、且实测宽度没被截断的单行命令，才在折叠行给“允许一次”；多行或被截断的命令、差异、URL、参数都要先展开。“全部允许 N”逐条写出每个调用的完整目标（D-362）。
- **理由。** 任何批准都发生在用户看到要执行的全部内容之后。
- **代价。** 窄窗口下多点一次“展开”；批量列表可能较长，限高滚动。
- **何时重议。** 折叠行可以安全地完整显示多行内容时。

## 123. 流降级后自动恢复

- **约束。** 桌面 Channel 不触发 onClose；降级后流既不退订也不恢复，只能靠手动重试。
- **选择。** 降级时退订，60 秒长退避后自动重新打开，打开成功再报 onRecovered。读快照期间暂存缓冲溢出、丢掉队首时，再读一轮快照，不把剩下的事件直接接上。区间以线上的 `first_seq` 为准，前端不改写折叠槽位的起点（D-363）。
- **理由。** 消除降级后的永久停摆和静默丢事件。
- **代价。** 长时间离线时每分钟会有一次快照读取。
- **何时重议。** Channel 能可靠报告关闭，或引入多窗口页面令牌时。

## 124. 对话列表的搜索与范围由核心分页

- **约束。** 前端只加载了前 100 行，在本地求交集会漏掉旧对话。
- **选择。** 搜索与范围都调用 `agentSessionList`，带查询与范围过滤分页；`agentSessionSearch` 只提供片段和命中消息 id。带正文命中的行打开到命中消息，搜索失败显示原因并清空命中（D-364）。
- **理由。** 结果完整，也不必把全部对话拉进内存。
- **代价。** 每次输入停顿后两次 IPC。
- **何时重议。** 核心的会话搜索直接返回带分页的完整行时，合并成一次调用。

## 125. 数据目录锁保证单实例

- **约束。** 第二个进程会把第一个进程活着的运行、完全权限、文件日志和子进程当成崩溃遗留处理掉；不能新增 schema。
- **选择。** 打开日志与存储之前，用标准库的 `File::try_lock` 对 `<数据目录>/spanbay.lock` 加独占建议锁。锁被别的进程持有时弹“SpanBay is already running”并以 0 退出，不碰存储。不引入 `tauri-plugin-single-instance`，它在 Linux 上依赖 DBus，只为把焦点交给已在运行的实例（D-365）。
- **理由。** Rust 1.89 起标准库自带文件锁，不需要新依赖；锁跟随进程，崩溃时由系统释放，不留死锁文件；macOS 的 Finder 与 Dock 本来就会激活已在运行的应用。
- **代价。** 用 `open -n` 或第二份副本启动时只看到提示框，焦点不会切到第一个窗口；建议锁在 NFS 一类网络文件系统上不一定可靠。
- **何时重议。** 用户经常从命令行或深链再次启动、希望直接回到已有窗口时，再评估单实例插件或本地套接字转交。

## 126. 三平台统一关窗即退出与退出检查

- **约束。** 网关与 Mock 可能是本地服务，但在三平台上标题栏三个窗口按钮应语义一致：关闭即关闭，最小化即最小化，放大即放大。把 macOS 红灯改写为隐藏会让关闭按钮表现得像最小化，且绕过关闭检查。
- **选择。** 三平台统一启用 `QuitMode::LastWindowClosed` 与关窗守卫（取代原 D-366 的 macOS 红灯隐藏方案）。关窗按钮（含 macOS 红灯、Windows `WM_CLOSE`、Linux 标题栏 `×` 与 WM 关窗）、⌘Q / 应用菜单“退出”和托盘“退出”走同一检查：有未保存更改或运行中任务/服务时弹窗确认，空闲则写出草稿后退出。最小化与放大保持原生行为；macOS 菜单栏图标在进程存活期间继续每 3 秒刷新状态。
- **理由。** 三个窗口按钮语义在三平台完全一致，消除“点红灯像最小化且没有关闭检查”的困惑；有网关/Mock/智能体在跑或未保存编辑时由退出确认兜底，不会静默丢工作。
- **代价。** 需要后台常驻网关且不想保留主窗口在桌面上时，改用系统最小化按钮（或 macOS ⌘H）而非点击关闭按钮。
- **何时重议。** 未来若明确新增可选的“关闭窗口时最小化到托盘”设置项时，再以显式开关形式提供。

## 127. 诊断只有日志一个出口

- **约束。** 打包后的 GUI 看不到 stderr，而 PRD 承诺持久化错误会记到后台日志。
- **选择。** 生产代码禁用 `eprintln!`，clippy 的 `print_stderr` 设为 deny，测试里放行；所有失败与提示都走 `spanbay_base::logging::log_line`。没有日志文件时以及调试构建里，同一行脱敏文本也写到 stderr，写入失败直接丢弃，不 panic（D-367）。
- **理由。** 只有一个出口，脱敏与轮转才能统一，lint 也能机械地强制执行。
- **代价。** 本地终端调试发布构建时，提示只在日志文件里。
- **何时重议。** 引入 tracing 一类日志框架时，要让它与 `log_line` 的脱敏和格式一致。

## 128. “复制诊断”附带擦除过的最近问题

- **约束。** 诊断文本承诺不含密钥、令牌、URL、主机和服务商名，排查问题却需要看到最近的失败。
- **选择。** 日志在内存里保留最近 20 条警告与错误。诊断只附时间、级别和模块，消息先按模式擦除 URL、邮箱、IP、主机形状的词（文件名也算）、引号与反引号里的文字和绝对路径，再截到 160 个字符。最后，整段诊断照常按已存秘密值脱敏一遍（D-368）。
- **理由。** 既能看出什么时候哪个模块出了错，又守住隐私承诺。
- **代价。** 消息会被过度擦除，信息有损；完整原文只在本机的 `logs/spanbay.log` 里。
- **何时重议。** 用户反馈诊断信息不够用，或打算提供“附带完整日志”的显式选项时。

## 129. 页面错误经 IPC 进日志并限量

- **约束。** Webview 的输入不可信，页面陷入错误循环时可能刷爆日志。
- **选择。** 错误边界的 `componentDidCatch`、window error 与 unhandledrejection 经 `app_client_error_save` 上报。核心只认 render、error、rejection 三种来源，其他记为 other；消息截到 2000 字符，堆栈截到 4000 字符，每个自然分钟最多记 20 条，丢弃的条数写进下一条被接受的记录，统一脱敏。前端遇到取消类错误不上报，上报失败也不再抛错（D-369）。
- **理由。** 页面自己的崩溃留下痕迹，错误刷屏也撑不爆日志。
- **代价。** 一分钟里超过 20 条的错误只留计数。
- **何时重议。** 需要按会话关联错误，或要上传崩溃报告时；目前没有遥测。

## 130. 错误呈现统一入口，高频错误补错误码

- **约束。** 核心错误大多是英文自由文本，前端有 54 处 toast 直接拼接 `e.message`。
- **选择。** 所有错误展示统一走结构化错误呈现入口，取消不提示，有稳定错误码的显示本地化句子，其余显示核心原句。新增 4 个错误码：`workspace_not_found`、`database_busy`、`disk_full`、`permission_denied`；失败的发送没写成历史时用 `ErrorDetail.history_unsaved` 标记（D-370）。
- **理由。** 先把呈现入口收拢到一处，再逐步给错误补码，不用一次改完上千条消息。
- **代价。** 没有错误码的错误仍显示英文。
- **何时重议。** 按日志统计出新的高频错误时，补错误码和 i18n 键。

## 131. 包体预算按模块首开闭包记账

- **约束。** 按应用 JS 总量计的门禁把懒加载块也算在内，总量实测 1,050,360 B，已超过 1,030,000 B 的硬顶，懒加载腾不出余量；D-266 写的重议条件已经满足。
- **选择。** 早期 Web 阶段按入口与各导航模块的首开闭包记账并设置共用硬顶（D-371）；迁移至纯 Rust GPUI 后，前端 JS 包体预算随之退役。
- **理由。** 懒加载块用到之前不影响首开，按模块记账能看出哪一块在长，拆分和懒加载也真正有用。
- **代价。** 应用 JS 总量只报告不拦，懒加载的对话框和设置的非最大页面只靠报告里的趋势盯着；基准里的 3% 余量吃掉一部分收紧效果。入口、CSS、关键 CSS 与字体仍是固定上限。
- **何时重议。** 报告里的总量持续上涨而首开闭包不动，或某个模块撞到共用硬顶时。

## 132. 运行结束通知默认关闭

- **约束。** PRD 与产品文档读起来像运行结束默认也会通知，实现默认只通知等你处理的事；改默认值会动冻结的设置注册表样本。
- **选择。** 默认保持“需要你时”，即审批、提问、计划批准与费用暂停；运行结束通知要在「设置 › 通用」里打开，只报 30 秒以上的运行。改的是 PRD §5 与产品文档的文案，不改默认值（D-372）。
- **理由。** 后台频繁弹运行结束通知很打扰，等你处理的事才必须马上看到；设置注册表不用动。
- **代价。** 想知道长任务跑完的用户要自己打开这个选项。
- **何时重议。** 用户普遍需要运行结束提醒，或注册表样本解冻时。

## 133. 安全与流相关的手写 DTO 先迁到生成类型

- **约束。** 手写 DTO 没有跨语言校验，Rust 给 AppError、审批或流信封加变体后照样编译通过，问题到运行时才出现；样本机制已经退役（§20）。
- **选择。** AppError、审批答复与权限规则、沙箱状态、运行事件信封与运行结果改由 ts-rs 生成，AppError 生成为 `AppErrorDto` 联合类型，手写名单只删不加。前端 `AppErrorException` 的附带字段从生成的联合类型推导：类型等价检查让 `APP_ERROR_KINDS` 与生成的 kind 对齐，每个附带字段在 `FACT_CHECKS` 里都要有必填的校验（D-373）。
- **理由。** 最危险的契约先拿到编译期保证，Rust 加变体或字段时 `npx tsc -b` 直接失败，也不必恢复样本机制。
- **代价。** 剩下 95 个手写类型仍没有校验；AppError 的前端形状是推导出的扁平类型，读起来比手写接口绕。
- **何时重议。** 手写名单清空，或 ts-rs 对带 flatten 的内部标签枚举的输出变化时。

## 134. 用量延迟卡读调用日志，按是否流式拆开

- **约束。** 用量汇总只有端到端延迟的总和，没有流式标记和首 token 时间，平均值主要由输出长度决定，“最慢服务商”因此会误导；不能改 schema。
- **选择。** 新增只读查询 `llm_usage_latency_modes_get`，从调用日志的成功调用按来源、服务商、密钥、模型、客户端与是否流式分组，汇总端到端时间与首 token 时间。延迟卡以流式调用的平均首 token 时间为主数，另列流式与非流式的端到端平均，最慢服务商按同一标准挑。日志里没有该时段的调用时，退回汇总里的端到端平均值并写明（D-374）。
- **理由。** 不改 schema 也能给出不受输出长度左右的指标，筛选在前端折叠，不用重复查询。
- **代价。** 日志保留期比汇总短，90 天、全部这类长范围的延迟只覆盖日志还留着的调用；延迟分位数仍暂缓。
- **何时重议。** 要做分位数或直方图，或要把首 token 时间写进汇总表时，这需要改 schema。

## 135. 用量统计只计已路由到服务商的调用

- **约束。** 网关在选出服务商之前拒绝的请求（Host/Origin 拦下、401 鉴权失败、未知模型、越权模型）以及自定义 URL 请求没有 `provider_id`，此前写进用量汇总后会生成独立的「未路由」服务商行，扭曲调用次数、失败率与「无密钥」分布。
- **选择。** 只有已路由到已配置服务商（`provider_id` 非空）的调用在写日志行的同一事务里累加到 `llm_usage_daily`、`llm_usage_minute` 与 `llm_usage_failures`，读取查询与前端折叠同步忽略 `provider_id` 为空的历史汇总行；未路由请求继续完整留在 `llm_request_log` 供调用日志排查（D-375）。
- **理由。** 统计聚焦各服务商的实际流量、费用与健康度，不再被未进路由的拒绝请求或临时地址干扰；调用日志仍保留完整排查依据，且不改数据库 schema。
- **代价。** 想查看网关 401/未知模型等路由前拒绝次数时，需要切到「用量与日志 › 调用」筛选，不能在「统计」的失败原因表里看到。
- **何时重议。** 网关需要单独统计入站鉴权/拒绝指标时，另建入站拒绝维度而不是混入服务商用量汇总。

## 136. 运行看板采用三视图自适应与左向右执行图

- **约束。** 智能体运行形态差异大，纯直出与短线性链强画横向 DAG 仅成孤岛，长迭代循环横向过宽；左侧导航已占「流程（Flows）」表示 HTTP 编排，且不能改 SQLite schema。
- **选择。** 运行看板拆为左侧独立主模块 `NavModule::Runs`（全宽全局并发与全量历史）与 `AppShell` 持有的 90% 视口共享模态框（对话头部/回合胶囊/看板点击均复用，含历史运行切换与 `步骤`/`执行图`/`时间轴`/`变更` 四视图，并移除对话右侧旧详情抽屉）。分层布局放 `spanbay-desktop::state::run_graph`，GPU 贝塞尔画布隔离在 `ui/dag_canvas.rs`；节点采用卡内微展开加右侧 7 类原型详情，审批仍走关卡区（§41）（D-376）。
- **理由。** 一份 `AgentRunTopology` 驱动三视图与焦点同步，兼顾并行可读性与直出密度，且布局和画布原语可直接复用于任务图与 HTTP 流程可视化。
- **代价。** 画布只读观察加快捷操作，不支持拖拽连线；卡片内截断长标题，完整内容在节点详情查看。
- **何时重议。** 当需要可视化拖拽编辑节点前置依赖时，在 `layout_dag_nodes` 之上扩展交互层。

## 137. 计划与待办扩展为向后兼容的结构化任务图

- **约束。** 计划模式此前仅交自由 Markdown，`todo_write` 限制单项 `in_progress`，规划与执行脱节且无法局部重试；新增表会触发单一基线 schema 备份重建。
- **选择。** 在 `AgentTodoItem` 追加带 `serde(default)` 的可选图字段（`depends_on`、`kind`、`role`、`group`、`run_id`、`attempt`、`summary`、`error`）及 `Failed`/`Blocked` 状态，复用 `todos_json` 列。`submit_plan` 支持结构化 `tasks`，核心用 Kahn 排序校验无环；批准时落库并附执行指引。计划卡内嵌任务图预览，节点详情支持重试、撤销改动并重试与跳过（D-377）。
- **理由。** 零 schema 变更打通“计划图确认 → 运行叠加子智能体 → 节点局部恢复”，保留节点内 ReAct 灵活性并避免整轮重跑。
- **代价。** 外层仍由模型配合 `todo_write` 推进，尚非硬隔离调度器；并行写目录隔离留待后续迭代。
- **何时重议。** 需要跨重启确定性外层调度器、写路径锁或 Git Worktree 并行隔离时，在下次 schema 升级窗口引入独立工作流表。
